# Original cockpit asset source proposal

This leaf preserves the existing original prototype interior: its eye, open windows, live panel, six bezel rings, copied control pivots and exterior. It adds restrained original repeating weave and roughness detail to Cloth, Leather, Dark and Black. It provides no manufacturer geometry, measured aircraft materials or C172 applicability evidence. Source and original tiles use the repository MIT license.

The proposed generator consumes the complete independently captured Godot 4.7.2 builder baseline before making candidate output. It does not reproduce sphere, cylinder, torus or box geometry with Blender primitive defaults. Captured geometry remains authoritative in each existing parent's coordinates. Only LeftSeatBack and RightSeatBack are re-expressed in their frozen original center and -8-degree X-rotation frame, with the matching object transform restoring the same composed geometry and normals; all other parts remain baked. `(x,y,z)` becomes Blender `(x,-z,y)`, and clockwise Godot triangle order is reversed for Blender/glTF. Sphere faces use flat storage with explicit captured custom normals to preserve retained degenerate pole normals; source normals are never recalculated or fitted. Node pivots remain separate identity-rotation objects at the exact design-reference rest translations. Existing normalized primitive UVs are retained. No geometry smoothing, subdivision, caps, seam repair, decimation, animation, camera, light or collider is authored.

`generate_cockpit.py` is source only. The three record schemas in its private baseline proposal must receive independent fixture-owner/Root agreement before execution. It requires the actual checked contract acceptance record, raw baseline and independent baseline review pins. The independent pre-output baseline must include the real primitive defaults, composed transforms, normals, UVs, winding and existing degeneracies; it must not use this generator to produce expectations.

Root's future admitted portable Blender invocation uses `--background --factory-startup`, Blender 4.5.14 LTS/build62c1db4208e8, the reviewed script, explicit `--baseline`, `--baseline-sha256`, `--baseline-review`, `--baseline-review-sha256`, `--accepted-contract`, `--accepted-contract-sha256`, `--reference` and a nonexistent `--output` directory. No tool is downloaded and no user preferences are changed or saved. Root separately admits executable/archive and script hashes. The generator writes only that explicitly supplied fresh staging directory, preserves failed outputs and does not implement adoption.

The staged outputs are `original-cockpit.blend`, `cockpit-source.json`, two 256x256 original PNG tiles and `app/cockpit/assets/original-cockpit.glb`. The editable file refers to its adjacent source texture files. GLB images must equal both source PNG byte strings; the generator rejects exporter re-encoding instead of fitting or rewriting accepted output. Actual Blender material-node recognition, color factors, image preservation, Godot synthetic import-root behavior and actual mipmap/material sharing remain unexecuted engineering gates. Source preparation is not evidence that these pass.

The fixed resource adapter validates the complete node/part/material roster before returning any node. It returns null and destroys its temporary tree on malformed/missing content; the existing builder/Scene must perform the separately allocated startup guard before opening native sessions. It reads no aircraft state, controls, device, origin or clock. The actual builder keeps its copied-control update formulas and live panel/rings. There is no procedural fallback, exterior replacement, hidden native tick or alternative camera.

Independent stdlib GLB checks and actual Godot-imported-array checks remain required: full topology/winding/normal/rest geometry correspondence, UV range, resource/color/image bounds, all copied-control endpoints and mixed input, fail-closed malformed assets, rights/source closure, and the frozen 60-view matrix in each of editor, portable and rebuilt-library contexts. Source/import success does not replace all180 original pixel reviews, existing camera/reading gates, performance observations or owner/hardware/pilot/phase decisions. Existing gaze/small-window limits remain explicit. The broader parent #23 remains open.

The independent baseline now requires each actual primitive's closed class/property ledger alongside its captured arrays. It includes common flags/AABB/material/UV2 properties, Box subdivisions, Cylinder caps/rings, Sphere hemisphere and Torus subdivisions. The original mesh getters supply values; no undocumented or documentation-default numbers are guessed. Native property types are checked during capture; fixed types survive JSON serialization. The independent baseline owner reviews this ledger before candidate generation. Geometry/export/adapter behavior is unchanged by this source successor.
