# Stationary ground provider API v1

This is the accepted interface prerequisite for [GROUND-PROOF #16](https://github.com/brettbergin/flight-simulator/issues/16). It reuses `GroundSample/v1`; there is no new wire schema, registry fingerprint or flight-model change. Contract tests exercise the engine-independent boundary. The separate [actual JSBSim consumer proof](../../fdm_jsbsim/ground/README.md) exercises contacts, convergence and fail-closed disposal within its original-cart scope.

Link `flight::ground_contract` and include [provider.hpp](include/flight/ground/provider.hpp). `flight::ground::v1::SurfaceProvider` supplies immutable prepared height-field data. `Identity` binds an exact `ContentRef` world, SHA-256 of the prepared contact surface and a nonzero generation. Generation changes only between completed boundaries; it never changes during an active `Boundary`. A provider cannot silently replace tile/data content under an existing digest.

The simulation host owns one calling thread. It prepares data before contacting this API; queries perform no I/O, download, waiting, scene access, physics mutation or hidden asynchronous work. A shared pointer to the const provider keeps it alive until all boundary queries complete. Returned samples own their data. Constness is an implementation obligation: the wrapper checks identity before and after every query, but cannot prove a dishonest implementation immutable. Content preparation and reference hashes remain world-package responsibilities.

`Boundary(provider, target_header, query_limit)` captures identity and the target simulation boundary (tick zero for initialization; target tick t before advancing to t). Default capacity is 256 query attempts; allowed capacity is 1..4096. Exhaustion rejects before invoking the provider. Invalid/mismatched responses and provider exceptions consume that attempt and poison the boundary; subsequent queries reject even if the provider appears repaired. Invalid requests and changed identity likewise fail it. A valid explicit missing response remains a successful query with a missing result; the consumer must block advancement. No force or aircraft integration occurs in the provider contract itself.

`sample(position)` asks at an exact WGS84 geodetic coordinate in radians/ellipsoid meters. The returned header and requested position must match exactly; a different position is not a successful result. Valid samples retain height in ellipsoid meters, unit normal in the query location's NED frame, material ID, effective static/dynamic coefficients and exact world reference. Normal points into free space and has negative NED Z; vertical/overhanging surfaces are unsupported. Dynamic friction must not exceed static. These are effective material coefficients for a declared contact mapping, not a substitute for tire/strut calibration or aircraft performance. Rolling friction belongs to the separate tire model; it is not invented from these fields.

Surfaces are stationary relative to Earth/ECEF. The JSBSim adapter must supply zero ECEF linear and angular surface velocity. A future moving deck or unresolved source datum requires a separately reviewed interface. The API accepts only already converted ellipsoid heights; it cannot treat an orthometric/MSL input as ellipsoid height. P4 geoid conversion remains #39.

## Missing data and atomic publication

All four existing missing reasons (`outside_coverage`, `not_loaded`, `datum_unresolved`, `invalid_data`) remain explicit. Missing data carries no substitute height, normal, friction or force. A renderer's coarse LOD and engine default sphere cannot silently become a successful contact sample.

The consumer must preflight all current CG/gear positions and a documented conservative motion guard in the same immutable prepared view **before controls, solver or clock mutation**. A known miss returns a blocked result: retain completed tick/state and unapplied inputs, publish no new contact and await a valid prepared view or explicit host recovery. Tile changes may happen only at completed boundaries and must pass the same readiness and geometric continuity checks. No aircraft location correction, runway attraction or enlarged integration step is a fallback.

The upstream callback returns scalar AGL, without a missing-data variant. If an unexpected callback miss, provider exception, response mismatch or capacity exhaustion occurs during integration, the consumer must abort and **discard the executive**. Keep only the previous completed immutable publication, invalidate the session and prohibit retry/resume on the partially mutated executive. Destroying that state is explicit fail-closed disposal, not rollback or a restored checkpoint. Restart/reconstruction requires its own accepted evidence; ground replay is unsupported in this contract.

Successful publication happens once, after a complete finite validated solver step and clock advancement. JSBSim remains the sole gear/contact integrator; Godot cannot apply a second collision force. The [consumer evidence](../../../docs/evidence/P1/ground-proof.md) demonstrates actual failure paths and flat/sloped behavior separately from provider tests; #20 still requires a public low-speed flight/ground runtime contract.

## Checks

The [native fixture](../../../tests/ground/contracts/native.cpp) uses original synthetic values, full uint64 ticks, malformed samples, wrong world/session/location, invalid normals/friction/digest/version, changed identity, explicit missing reasons, bounded attempts and provider lifetime. Run through the accepted bootstrap/CTest or build `tests/ground/` standalone with the pinned compiler. These checks ratify the query API only; they do not close #16.
