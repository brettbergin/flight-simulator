# Original flight reconstruction proof

Issue #17 is a bounded engineering experiment. It implements **replay from the beginning**, not hidden-state snapshot deserialization or a product save system. The observed guarantee applies only to the pinned original synthetic aircraft, matching executable/shared-library/compiler/contract/model bytes, dry ISA without stochastic weather, a fixed 120 Hz host, and a canonical paused boundary after 600 simulated seconds. Contact/terrain reconstruction remains unsupported even after a separate ground proof lands.

Build with the [pinned bootstrap](../../../tools/bootstrap/README.md), install the locked schema validators, and run:

```powershell
npm ci --ignore-scripts --prefix schemas
node --test tests/replay/declarations.test.mjs
node tests/replay/proof.mjs
```

CTest's `replay_reconstruction` invokes the same native experiment with its actual target executable. The CLI optionally accepts an executable path and an output directory; use a separate output directory for each experiment. `.local/replay-proof/` contains local requests, actual loaded-module identification, original admission/event histories, recipe, versioned declarations, sampled traces, timing and a compact report. Raw local identification paths are engineering output; the compact report excludes them.

The host independently computes SHA-256 of the actual executable and the actual library path reported by the address-based native loader, validates model/schema hashes, and binds adapter fingerprint, compiler and engine version into an exact identity. The reconstructed process compares the persisted identity to the trusted current host identity before model parsing or integration; it also checks its actual adapter fingerprint/compiler/version. The host rechecks binary/library/model bytes after both child processes. Checksums detect corruption and compatibility; they are not authentication of a maliciously rewritten archive.

## Recipe and experiment

The [private typed recipe](include/flight/reconstruction/recipe.hpp) uses bounded little-endian binary format `FSRPLY01`, version1, IEEE binary64, seven host identity strings, checkpoint tick, the original validated `FSFDM001` initialization request, and up to4096 original admission records. Strings are printable ASCII≤256 bytes (stable IDs≤128); total bytes≤4MiB including a64-character SHA-256 of the complete payload. Unknown version/kind/flag, trailing/truncated bytes, nonfinite values, wrong identity, out-of-order receiving boundaries, unsupported axes/assists and an unpaused terminal boundary reject. Native configuration decoding reuses the accepted adapter. This private format is not a new supported public contract.

A caller-owned recording wrapper exposes registration, admitted control/lifecycle inputs and `step_fixed`; it never exposes wall-budget advancement. Recording preserves cross-lane admission order and successful receiving boundaries, including source registration changes and pending future commands. Reconstruction creates a **fresh executive in a new process**, repeats initialization/trim, then re-admits records at their original completed boundaries and runs every fixed step. It never assigns visible position/velocity to simulate hidden-state restoration. A replay that remains paused before its next required step fails; exceptions discard the incomplete executive.

The experiment admits seq1 for tick60000 before seq2 for tick121, then later admits seq4 for tick72001 before seq5 for tick20001. This deliberately reverses arrival/execution order. It also registers a second source after startup, admits its pending tick72020 command, records pause/resume and time scales with original lifecycle sequences77..81, and pauses at tick72000. After reconstruction, old source/lifecycle sequences must still reject; valid new sequences continue. The next7200 ticks apply both previously pending commands and the new command exactly once, with active fuel consumption.

Before measuring, the comparison criterion is **exact same-build canonical telemetry equality**: a rolling SHA-256 chain covers full aircraft, atmosphere and diagnostic serialization at every one of72000 reconstruction and7200 continuation steps. Checkpoint, final state, one-second continuation samples, applied commands, initialization, original admissions and observed events also compare byte-for-byte. This tests the available engine/fuel/mass, acceleration, orientation, weather and controls through continued evolution; it does not prove arbitrary unmodeled state or a continuous-time accuracy bound.

The proof rejects every packet truncation, corrupt/trailing bytes, every identity component mismatch, a correctly rehashed newer version, malformed/reordered/duplicate registrations and command sequences, unsupported assistance, out-of-range cuts and noncanonical boundaries. Node checks the actual public shapes, provenance and expected pending commands. Cross-file declaration tests reject corrupted blobs, mismatched session/build/schema/seed/count, unsafe paths and unsupported restore claims.

## Accepted declaration semantics and limits

`SessionManifest/v1.restore_capability` and `Checkpoint/v1.restore_capability` are `replay-from-start`, with explicit evidence ID `p1-original-fixed-step-reconstruction-v1`; never `complete-checkpoint`. `Checkpoint.replay_until_tick` equals its tick. Its blob is a reconstruction recipe, not an instantaneous solver snapshot. The manifest's `command_log` points to the private receiving-boundary admission wrappers (registration, ControlCommand/v1 and SessionControl/v1), while `event_log` points to independently sequenced observed OperationalEvent/v1 records. Events cannot substitute for original source sequence/admission history. `ReplayHeader/v1` binds the exact manifest, build/contract/seed/clock, admission count and digest. [Declaration validation](../../../tests/replay/proof.mjs) checks cross-file identities and content digests in addition to strict schemas.

This ratifies the existing declarations for the **measured physics reconstruction capability**, not complete application resume. Fractional scheduler budget/debt, UI mailboxes, thread/recorder state, streaming history, persistence durability, profiles/migrations, random weather, engine/propeller/electrical/failure models, ATC and procedural state are unsupported. Neither visible-state teleport nor `FGPropagate::SetVState` captures an entire executive. Initial product resume remains reviewed restart checkpoints until the integrated host can establish a canonical paused/drained boundary or a reviewed scheduler-state contract, and proves all participating subsystems.

Reconstruction cost is linear in elapsed ticks. The report records actual initialization-inclusive experiment wall time and separately accumulated solver-step time; total also includes hashing, serialization and the following60 seconds. A30-second engineering budget for this ten-minute reference case is provisional, not a universal performance guarantee. The [evidence record](../../../docs/evidence/P1/save-proof.md) retains measured results and scope. No user-visible save success or training qualification is implemented here.
