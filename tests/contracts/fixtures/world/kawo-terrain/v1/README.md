# KAWO terrain schema-only fixtures

These are handwritten JSON shape expectations for the proposed compiler contract,
not compiler output or a usable airport. No fixture was generated by the compiler,
schemas, PROJ, raster decoder, or native ground component. No test has been run
by the source author of this private packet.

`inputs.valid.json` is a structurally valid descriptor with fictitious paths.
`airport-geometry.valid.json` is a shape witness with deliberately synthetic,
simple 1024m centerlines and 16m/32m widths. Its labels identify schema tuple
positions, not real runway geometry or operational bearings. Anchor words alone
are the actual phase-A frame constants required by this fixed schema.
`receipt-fields.valid.json` contains the other hand-authored receipt fields;
the test adds the independently authored geometry object to make the full receipt.
`rejected-binary64.json` contains literal malformed/nonfinite scalar witnesses.
Mutation tests supply other rejected shapes without deriving baseline expectations
from a schema.

Repeated a/b/c/d/e/f digest characters are explicit synthetic grammar tokens.
They are not raw airport/dossier/tool-qualification/payload/decoded-plane hashes.
The literal `{}` PROJJSON strings are likewise schema-only string tokens, not
actual selected operation records. The four definition strings, operation
directions/areas, source byte pins, tool pins, grid constants, and anchor words
are transcribed from the reviewed source/draft and phase-A/vertical observations.
This mixture is intentionally not a qualified compiler receipt; it permits
independent schema tests before actual compiler product values exist.

The tests use existing pinned AJV 2020 through `schemas/package.json`, without
coercion, defaults, field removal, project helpers, subprocesses, or acquisition.
Root may run:

```text
node --test tests/contracts/kawo-terrain.test.mjs
```

Schema validation closes fields, types, fixed rosters/pins, finite binary64
representations, constants, and represented nonnegative gradient/span/residual
bounds. It cannot establish strict raw-byte parsing, duplicate-key/BOM/depth/value
budgets, ordinary-file identity, canonical serialization, actual decoded samples,
operation PROJJSON/axis relations, all-valid count arithmetic, min/max/facet/ring
relationships, source/ground digest equality, native agreement, rights approval,
or external `validateSourcePair` preflight. The last test deliberately demonstrates
those limits. Existing independent contract gates must still pass; schema success
is neither product acceptance nor consumer implementation authorization.
