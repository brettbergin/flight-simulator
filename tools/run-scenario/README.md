# Development scenario boundary and private transport v1

The [native harness](../../native/fdm_jsbsim/README.md) consumes no untrusted JSON parser in the portable runtime. This Node/Ajv frontend validates the complete accepted ScenarioManifest/v1 and ControlCommand/v1, rejects omitted unsupported state/assists/actions, verifies the exact original aircraft inventory and encodes a bounded internal request. Native typed validation repeats boundary checks before parsing approved XML. Emitted v1 JSON is revalidated and bound to the complete request, not merely its final tick.

`runner.mjs` exports `checkInput`, `encodeRequest`, `verifyModel`, `validateOutput` and `runScenario`; ordinary CLI usage takes scenario JSON, arrival-order command array JSON and output directory. Exceptions/nonzero runner status fail the request. Files under the output directory may be overwritten deliberately; choose a separate directory per experiment. Inputs, exact request/telemetry/library/build/content/contract hashes and requested/accepted initialization are retained locally. Current restore claims are unsupported/unproven.

The private binary format is little-endian, IEEE 754 binary64, magic ASCII `FSFDM001`, format `version:u32 = 1`. Maximum request 4 MiB, IDs 1..128 ASCII stable-ID grammar, command count 4096, duration ≤600 seconds. Truncated/excess/trailing bytes, unknown flags/rates/types, nonfinite values, mismatched metadata, unauthorized source and nonmonotonic per-source arrival sequences fail. It is neither a new public contract nor a general content installer; changes require coordinated producer/decoder/test changes.

| Order | Encoded value |
|---|---|
| Header | magic:8 bytes; version:u32; Hz:u32; purpose:u8 (runtime=0/convergence=1); trim:bool:u8 (0/1); duration_ticks:u64; sample_interval_ticks:u32; seed:u64; session ID |
| Aircraft | position (lat/lon/ellipsoid height):3f64; ECEF:3f64; quaternion (w,x,y,z):4f64; ground-relative body velocity:3f64; Earth-relative body rates:3f64; mass:1f64; datum CG:3f64; flap/gear/trim:3f64 |
| Atmosphere | pressure/temperature/density/humidity:4f64; wind toward NED:3f64; turbulence NED:3f64; model ID |
| Commands | count:u32, then target_tick:u64 / sequence:u64 / source ID / authority:u8 (pilot=0 only) / assistance profile ID / axes (roll,pitch,yaw,throttle,mixture,left_brake,right_brake,trim):8f64 |

An ID is u16 byte length followed by exact ASCII bytes. All uint64 wire strings become BigInt before encoding. The omitted fields are deliberately unsupported and rejected: nonzero initial acceleration, initial systems/contacts, non-initializing validity, active assists, system-control payloads and scheduled scenario actions. Tick-zero, matching seed/session/clock, supported world/aircraft refs and static configuration are checked before encoding. Native submission retains original arrival order independently of execution; CLI preloads its bounded script and expands only its explicit horizon to run duration.

Output starts with one strict `fdm-initialization/version 1` receipt, AircraftSnapshot tick 0 and diagnostics tick 0. Commands appear at successful application ticks; every configured sample boundary and final tick emits AircraftSnapshot, AtmosphereSample and diagnostics in that order. Full context checks require exactly this ordered/count-complete stream, one session/clock/seed, exact applied commands and consistent initialization fuel/controls/weather. Diagnostics have explicit allowed fields and finite bounds. Timing is a separate sidecar, excluded from canonical repeatable telemetry; scope is `Session::step_fixed`, excluding output serialization. Source fingerprint is independently recomputed from actual adapter inputs before provenance publication, and the actual loaded shared-library path is resolved inside the native process before hashing its bytes.

Relevant checks: [wire tests](../../tests/fdm/frontend.test.mjs), [actual output corruption tests](../../tests/fdm/integration.test.mjs), [native parser tests](../../tests/fdm/native.cpp), [transport fixture generator](../../tests/fdm/make-transport-fixture.mjs). The native API serves game clients directly; development transport/Node are not portable-release dependencies.
