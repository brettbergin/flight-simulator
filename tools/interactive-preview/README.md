# Whole-flight engineering preview

Windows x64, PowerShell 7+, original synthetic flight model with tricycle gear. The player includes an original high-wing aircraft, procedural cockpit interior with a live physical dashboard, synthetic airfield scenery, responsive graphical instruments, camera controls, a local airfield map, smooth pilot input and procedural sound. This is not a C172, validated landing lesson or qualified training device. Instruments display derived native truth, with TAS and ellipsoid height explicitly labeled.

Build the pinned native toolchain first, then:

```powershell
$proof=(Get-Content .local/export-proof/latest-run.json -Raw | ConvertFrom-Json).root
./tools/interactive-preview/run.ps1 -ExportProofRoot $proof -ToolchainRoot .local/toolchain
$run=Get-Content .local/interactive-preview/latest-run.json -Raw | ConvertFrom-Json
& (Join-Path $run.payload 'launch.ps1')
```

When reusing an already verified native build in another checkout, pass its directory as `-NativeBuildRoot`. The selected build's compiled fingerprint must match the current facade; source/runtime checks still run. Staging writes only to a fresh preview directory.

No accounts or runtime Python/Node/compiler required. Launcher requires PowerShell 7 and puts userdata beside the fresh payload, with an empty PATH and app-local native libraries. `-HeadlessSmoke` runs an explicitly automated pilot-API driver, plus pause/reset/control/close assertions. The package gate compares exact editor/exported records (except fresh session IDs), verifies all seven actually loaded native module paths/hashes and the full PE/CRT closure, pins the new model, and reruns the combined loop with a separately rebuilt JSBSim DLL in a Unicode path. `-VisualSmoke` is a separately scheduled GPU diagnostic with fifty-nine viewport captures, including both runway ends, low approach, intersections, fields, coverage boundary/corner a camera-only sweep/return, six named landmark observers, reciprocal runway selection, compact locator and fault views while the native aircraft stays paused and unchanged, plus four close aircraft-shell views and sixteen short moving chase/orbit frames. The moving fixture advances13 native ticks per camera mode; the older controlled_native_ticks120 counter describes its separate control test. Final exported image/package qualification is retained in the issue evidence, not inferred from a capture count. `-Airborne` starts the human mode airborne; default is ground-ready with brakes held. A watchdog limits smoke processes.

Choose Resume, runway or airborne start from the initial menu. Arrow keys roll/pitch (Down raises nose), A/D yaw and nose-wheel steering, PageUp/PageDown or W/S throttle, [/] trim. X explicitly sets throttle idle through the next normal pilot command; B toggles brake hold; Space momentary both brakes; Q/E individual brakes. The named smooth keyboard preset moves roll/pitch/yaw at0.9 normalized units/second toward solved-start bias plus explicit gains0.35/0.15/0.25. Throttle integrates0.25/s and trim0.08/s; aliases contribute once. This input mapping has no attitude/velocity feedback. P or Escape opens/resumes the pause menu; quitting is a deliberate menu action that joins the worker and retires audio. G starts a fresh ground session; F fresh airborne; R restarts the current start.

For a local flying goal, pause and choose **Landmark route**. Select a suggested itinerary or up to four different landmarks, choose **Use selected route**, then resume from the menu. The optional card and map marker show the selected synthetic target. Pause and reopen the board to choose **Next leg (manual)**, **Stop route**, either pavement-end **Return** reference, or **Show aids**. Routes remain in memory for the current flight and clear on a new session. Range is horizontal kilometres; bearing is from the original airfield anchor's north. Progress is manual. Hardware defaults use linear full throw when a selected axis is bound, and the keyboard smooth preset remains available through Defaults.

Camera, panel and sound choices cannot command the aircraft.

Ground contacts and wheel forces come from native state. TAS subtracts copied NED wind/turbulence from earth-relative velocity; it is not IAS or a modeled airspeed sensor. Altitude is WGS ellipsoid height, not MSL/barometric altitude; VSI is kinematic and heading true. Body yaw rate is explicitly labeled rather than pretending to be a turn/slip instrument. No C172 limit arcs, RPM or unsupported sensor behavior are invented. Sound is original synthesized presentation driven by throttle/speed, not measured engine acoustics.

The fixed 120 Hz player retains bounded wall-clock debt; a stall pauses visibly and requires an explicit fresh restart. Unknown coverage/native faults stop the loop visibly. Choose **Flight review** from the pause menu to inspect captured observations. First/Previous/Next/Latest and the arrow-key slider select real samples; the graph selector shows true airspeed or ground speed in knots, ellipsoid height in feet, vertical speed in ft/min, or fuel in kg. Height is still ellipsoid height, and speed is derived native truth. Stored values remain SI; presentation uses the dashboard's accepted conversions. The separate recorded path and cursor never move the live aircraft or camera.

Recording targets two observations per simulated second for at most20 simulated minutes. Late samples and missed targets are distinct, and graph/path lines break at gaps. Sampled planar track and fuel change use only captured observations. This is not the complete trajectory, command history or flight replay. Once verified native time advances, restart/another named start/quit asks for explicit discard; Cancel keeps the flight paused and its review available. Failed new initialization retains the old closed prefix. The current memory recording disappears on exit or process loss. See [recorded review evidence](../../docs/evidence/P2/observed-flight-review.md).

In Flight review, **Save new review** writes the current paused flight into a new explicitly chosen `.fsreview.json` file on local Windows NTFS. Existing files are refused; choose another name. **Open review** validates a selected saved file before displaying it as **OPENED FILE / HISTORICAL**. **This flight** returns to your current recording. Saving while viewing an opened file still saves the current flight. Scrubbing, opening, cancellation and errors leave the current airplane unchanged, and Back returns to the paused flight. Saved observations do not resume a flight or bypass restart/quit confirmation.

File feedback provides **Details** with selectable full paths when recovery is required. An unverified save can leave an available temporary or an uncertain target; preserve those files for inspection and choose a fresh name for another save. The feature does not automatically overwrite, retry, save a profile or upload anything. File hashes detect corruption; they do not verify the author or pilot/aircraft validation.
