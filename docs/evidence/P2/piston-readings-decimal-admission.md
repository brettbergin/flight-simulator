## Failure and repair boundary

The preserved [contract/reference evidence](native-wire-number-contract.md) shows pinned Godot JSON numeric conversion returning the adjacent lower binary64 for native decimal `0.059999999999999998`. The original token and typed native held `0.06` correctly round to the same bits, little-endian `b81e85eb51b8ae3f`. NativeReadings rejects the decoded contradiction. Native FCS drift, model calibration and receipt reserialization are not established causes.

The candidate repair keeps native JSON publication bytes and typed control authority. Stateless `FlightWireNumbers.decode_binary64` converts a bounded complete batch with the production C++20 core. `app/simulation/native_wire_decoder.gd` transduces all original strings and numeric tokens to collision-safe placeholders, uses Godot for transformed container/literal grammar, invokes one native batch and restores an owned Dictionary. It rejects duplicate decoded keys, invalid Unicode, malformed complete roots, caps and partial conversion. It introduces no second recursive JSON grammar and no fallback parser.

The source targets are `native/godot_bridge/src/wire_numbers.hpp`, `wire_numbers.cpp`, registration in `bridge.cpp`, the frontend decoder and narrow `session_facade.gd` delegation. The reader audit includes direct proof, airborne and interactive previews, flight-camera checks, steady-wind bridge checks and independent native-template mutation tests. NativeReadings, EngineStatus, wire semantic admission and recorded-review contradiction checks remain exact. No epsilon, snap to held values or decimal rewriting is introduced. Preset/content/manifest parsers and tagged binary64 recorded-review archives retain their separate formats and policies.
