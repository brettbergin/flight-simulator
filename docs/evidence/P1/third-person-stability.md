# Third-person motion stability

Issue [#110](https://github.com/brettbergin/flight-simulator/issues/110), following accepted [#108 / PR109](https://github.com/brettbergin/flight-simulator/pull/109), main `eb7bfb8e82cfb8796286bbbafea0e00ec6255701`. The owner clarified that small jolts in third-person aircraft motion were the remaining problem. This is a private engineering-preview presentation correction; frozen package/capture review remains pending until the integrator records the final artifacts.

## Behavior and authority

Previously, the aircraft jumped directly to the latest native publication while the camera eased its absolute world position toward that moving target. The body and camera could therefore occupy different phases of translation. The new private pose buffer retains only consecutive accepted native120Hz endpoints in the same rendering frame. Position interpolates linearly and rigid attitude uses shortest-arc quaternion interpolation. Fractional tick debt selects alpha, bounded to0–1. Once adjacent history exists, presentation is one fixed tick behind current simulation time: nominal `1/120 s = 8.333 ms`. It never extrapolates.

A multi-tick native batch obtains the last adjacent endpoints by stepping n−1 ticks and then one tick, preserving the actual completed count, command/event order and debt. Zero-step render frames retain the existing pair. Invalid/nonfinite/nonrigid poses reject and clear history; duplicate/gapped ticks or changed sessions collapse to a fresh endpoint. Pause collapses to actual native pose; faults clear presentation history and retain explicitly historical native truth. Reset joins the old worker, starts a fresh declared recipe/session, and clears prior render history. No rendering delta becomes solver dt or an aircraft-state filter input.

Chase/orbit cameras use the same presented translation as the aircraft. Only viewing offset eases when the pilot changes a view/look direction; that easing does not lag the aircraft's world translation. Repeated diagnostic draw calls with zero elapsed viewing time do not advance this filter. Cockpit/body presentation remains congruent. Map position/heading, graphical instrument readings, contact/WOW/force values and held pilot controls use raw copied native state. A visually interpolated transform is never published as an `AircraftSnapshot/v1` or applied to the solver.

The native API, fixed120Hz clock, model inventory, prepared world, engine/gear/friction, wire records and assistance profile are unchanged. This is not a flight-state stabilizer, C172 handling correction or production [#20](https://github.com/brettbergin/flight-simulator/issues/20) simulation-facade contract.

## Bounded checks

The original [pose buffer](../../../app/proof/interactive/flight_render_pose.gd), [synthetic checks](../../../app/proof/interactive/flight_render_pose_checks.gd) and [native/camera checks](../../../app/proof/interactive/flight_camera_checks.gd) make the scope inspectable.

Body/camera maximum position error was3.846×10⁻⁶m against independently evaluated continuous presentation motion; maximum basis-axis difference was6.664×10⁻⁸. These are bounded float-arithmetic checks, not flight accuracy or sensor budgets.
- Endpoint/no-extrapolation, shortest179°→−179° arc, owned values, explicit fault clear, gap/duplicate/session reset, scale/shear/reflection admission and nonfinite pose/alpha behavior are covered by presentation guards/checks. Native dynamics are not invoked by these synthetic tests.
- Actual integrated headless checks passed for five host schedules:30/60/144/240Hz and irregular cadence totaling one wall second. Each admits the same explicit nonzero typed pilot command at tick1 before advancement, with no frame-polled input. An independent native worker runs120 ticks in32+32+32+24 batches. Aircraft/atmosphere numerical wire bytes, held axes and relevant worker data match at the endpoint after replacing only the fresh session-ID token; tick120, zero debt and one command submission agree. The actual applied command is retained in an isolated diagnostic trace and matches the unsplit worker record exactly after only session-ID replacement; the baseline also verifies every command field and payload value (numerical tolerance10⁻¹²), applied exactly once.
- A clearly synthetic observer pair around an actual copied pose checks same-frame chase translation, camera-relative offset/gaze, raw map position and native instrument snapshots. Repeated observation preserves actual read_state, intent and command counters. Native pause, fresh ground reset and explicitly synthetic retained/fault presentation exercise history invalidation.

These fixed-input schedules do not imply that separately sampled keyboard/gamepad input yields identical commands or trajectories at different render rates. Final frozen editor/export/rebuilt-DLL runs must reproduce the relevant actual integration checks; development results alone do not accept a distributed payload.
