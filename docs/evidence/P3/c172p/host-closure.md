## New material source findings

**The conventional electrical system is actively C172S-derived.** `Nasal/electrical.nas` header lines 2-7 describes its C172S POH/maintenance-manual basis. Conventional `c172p-set.xml` loads it, and lines 628-635 instantiate and enable its updater. This is not confined to selecting the optional 180 hp engine. `Systems/systems.xml`22-28 deliberately disables the native electrical path in favor of Nasal. The starter bus written by this model is consumed by `Systems/engine.xml`70-86. Its applicability to the intended C172P installation or a separately sourced replacement is unresolved. This is an applicability problem, not an invented absence of a project license grant.

**The airspeed path is not a direct JSBSim IAS gauge.** Candidate `Systems/systems.xml` configures native FlightGear pitot/static; `Systems/instrumentation.xml`33-38 binds their selected pressures. The inspected native `airspeed_indicator.cxx`107-108 computes CAS while publishing the node named indicated-speed. Candidate `Systems/indicated-airspeed.xml`47-54 then uses a separate POH-referenced error table to write solver `velocities/vias-kts`. Raw auxiliary IAS substitution changes semantics. Applicable IAS-CAS reference and execution ordering remain unresolved. Native static source selection also uses C182S-derived source comments in `Systems/static-sources.xml`; no C172P alternate-static calibration is adopted.

**Current source defaults cannot be treated as a closed normal state.** main.xml916-943 defaults complex procedures/oil/carb icing/starter management off, but engine.xml695-716 drives damage/oil/carb/contamination flags from the complex flag. Nasal timers start at FDM initialization even when features are off and may write neutral reset values. Saved state may override defaults. State manager and autostart explicitly assign mixture, throttle, trim, starter, engine running and securing state; they are preparation assistance, not neutral display behavior.

**Host scheduling differs from our solver boundary.** FlightGear copies controls/fuel/weather into JSBSim once before a batch of Run calls and publishes after the batch (`JSBSim.cxx`517-551). The Generic updater uses elapsed-time deltas multiplied by simulation speed, lifecycle/reset callbacks and frame/timer scheduling. Engine, oil, icing and electrical update periods differ. Nasal engine coughing includes randomness and transient kill/revive callbacks. No deterministic fixed-tick/pause/save equivalence has been established. Explicit future event/seed/lifetime ownership is required before a port could be honest.

## Remaining closure blockers and next bounded work

1. Decide whether the future deliverable is a licensed derived numerical model with explicitly authored native services, or a much larger faithful FlightGear host/service port. Neither is authorized by this source investigation. Do not adopt the whole host just because its source is available.
2. Resolve the retained property-family graph to exact readers/writers, runtime-built names, initial values/types, alias targets, listener lifetime, update ordering and native conversion boundaries. Current 24-family ledger is a source-backed proposal, not a complete executable whitelist.
3. For any retained Nasal service, recursively pin its interpreter/bindings, SimGear/property native dependencies and all service calls. For replacements, record law/applicability provenance and derivative/source obligations; an independent implementation is not automatically established by renaming code.
4. Specify and review a land/one-engine/dry/manual transformation whose every removed writer and surviving consumer is accounted for. Existing source is multi-variant, not an already isolated 160 hp land profile.
5. Join #171 certified/manual/reference feasibility and a separate runtime/profile/interface decision; retain null unsupported reference cells and no numerical tolerance inventions. Only then could import/package/validation work be proposed.
6. Owner/integration chooses distribution boundary and the concrete GPL/source package policy described in [rights-obligations.md](rights-obligations.md). No project relicensing or source package is created here.

Primary URLs and byte identities are in [host-source-index.json](host-source-index.json). The metadata records decoded source SHA256 separately from Git blob SHA1 and host HTTP response hashes. No primary XML/Nasal/C++ content, licensed manuals, tables, textures, sounds or models is stored in these metadata documents. No runtime outcome or aircraft performance claim is made.
