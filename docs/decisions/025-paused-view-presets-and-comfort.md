# ADR025: Paused cockpit lookout presets and camera comfort

Status: **private proposal, not accepted**; a bounded leaf under [HUD-CAMERA #26](https://github.com/brettbergin/flight-simulator/issues/26). Consumers wait for independent review and a protected contract merge. Partially supports UX-010 directly and UX-011/013 through focus/readability/release guidance; PRD-015 is a supporting presentation prerequisite, not a new assist. Broad #26, human/hardware/pilot, C172 and phase gates remain open. Basis: ADR007/008/017/019 and the scoped #179/#192 gaze-layout findings.

## Decision and boundary

Add a **Views** page to the already-paused ordinary flight menu. It offers the existing Cockpit, Panel, Chase and Orbit modes plus **Forward horizon**, **Left window** and **Right window**. It helps the player return to predictable original cockpit lookout directions during circuit practice. No live selection hotkeys, new InputPreset action IDs, head tracking, eye translation, calibrated Cessna sight-picture claim or automatic viewpoint following are introduced.

The ordinary Scene inherits camera construction/mode helpers from `interactive/preview.gd` but presents aircraft and camera from `Facade.visual_pose()`. Apply this leaf to ordinary `app/simulation/flight_scene.gd`, preserving the separately runnable proof preview and its four-mode API. Camera state is presentation only. No native/wire/model/schema/settings/archive mutation or aircraft control is authorized.

## Exact choices, frame and FOV

Preset IDs are the seven exact Strings below. Modes0/1/2/3 keep their existing meaning. Cockpit-local visual axes are right/up/aft: aircraft forward is local -Z, left is -X. Transform directions and the existing physical eye by the **same rendered aircraft basis/translation**, not the latest raw endpoint. Interior camera up remains the rendered aircraft's local +Y; no world-horizon stabilizer is added.

| ID / visible label | Existing mode | Base direction at zero free look | Default FOV |
|---|---:|---|---:|
| `cockpit` / Cockpit | 0 | Existing normalized `(0,-0.268,-1)` | 72 degrees |
| `forward_horizon` / Forward horizon | 0 | `(0,0,-1)` in aircraft-local visual frame | 72 degrees |
| `left_window` / Left window | 0 | `(-1,0,0)` | 72 degrees |
| `right_window` / Right window | 0 | `(1,0,0)` | 72 degrees |
| `panel` / Panel | 3 | Existing normalized `panel_focus-eye` | 58 degrees |
| `chase` / Chase | 1 | Existing external eye/look-target formula | 72 degrees |
| `orbit` / Orbit | 2 | Existing external eye/look-target formula and floor constraint | 72 degrees |

“Forward horizon” means aircraft-level forward direction, not a gyro-stabilized or guaranteed visible terrestrial horizon. “Window” names a look direction, not a promise of unobstructed side glazing. Preserve the original `cockpit.eye=(-0.27,0.67,-0.92)` visual-local meters, current panel focus, near plane0.1m, cockpit/exterior visibility rules and panel-viewport update rules. Do not move the eye to avoid a pillar or hide source geometry.

The page shows current view and FOV and offers a finite35–90-degree FOV control, preserving existing bounds. Each new preset choice seeds its listed default FOV in the **draft**; a subsequent explicit draft FOV edit wins on Apply. Existing mapped view actions retain their current default-FOV reset behavior. Live wheel/zoom actions retain their current35–90 interior FOV and6–40m external distance rules. This page does not edit external distance or reset a previously chosen distance as a side effect of Apply.

Use one exact, copied, three-key settings value: `{preset:String, fov_deg:float, external_response:String}`. No unknown keys, StringName coercion, nonfinite number or out-of-range FOV is admitted. `external_response` is exactly `smooth` or `immediate`. Defaults are `cockpit`,72.0,`smooth`. The optional pure `app/camera/view_policy.gd` seam is stateless: `defaults()->Dictionary`, `validate(value:Variant)->Dictionary` exactly `{ok:bool,error:String,value:Dictionary|null}`, and `describe(preset:Variant)->Dictionary|null` exactly `{mode:int,base_direction:Array[float]|null,default_fov_deg:float}` for an admitted exact String. Direction is null only for Panel/Chase/Orbit, whose existing host formulas remain authoritative. Invalid values do not change host or page state; success returns owned values and empty error, rejection returns nonempty error and null value. Do not place user code, paths or arbitrary camera vectors in this seam.

## Draft, apply and lifecycle

Entry requires the current adopted session to be identity-qualified, `paused=true`, host mode `paused`, with a valid current visual pose; no initializing, closing, archive/discard/review/Controls/Wind/Audio/Scan/Route/First-flight owner is active. Open only from the paused menu, after its existing ordinary pause/capture-retirement boundary succeeds. A live direct call rejects without implicitly pausing. The page itself does not call Facade, poll/sample/reconfigure Mapper, or resume the flight.

Open copies the current settings into an independent draft. No camera preview changes are made while editing. **Apply** validates the complete draft and current opening-session identity, then atomically adopts presentation settings, zeroes free-look offsets and reseeds the local follow offset on the next coherent draw. It returns to the still-paused menu. **Cancel**, Escape and page Back discard the draft and preserve camera preset, free-look offsets, FOV, distance and response exactly; no native or mapper mutation follows. Label actions Apply and Cancel, with Cancel as initial/default focus. Restore defaults changes only the draft until Apply. Repeating an identical Apply is presentation-idempotent and cannot change an input generation or native tick. Stale-session/retired callbacks reject; replacement, failure, close and quit retire the page before another owner can use it.

Choices last only for the current session. After a **fully successful fresh-session adoption**, reset the new settings to Cockpit/72/smooth and existing default distance13m, with zero look angles. A rejected selection, canceled discard or failed restart must not overwrite the previous settings merely because a new attempt was requested; if existing restart failure suppresses geometry, do not claim the old view is still current. No autoload, automatic preference file, InputPreset field, observed Recording field or review/archive migration is introduced.

The existing four mapped view actions select the four traditional presets and reset free look/default FOV as today, preserving the selected external response. `view_cycle` remains the existing mode cycle0→1→2→3→0: a new side/horizon preset is mode0, so its next cycle selects Chase. Existing `recenter` resets only the free-look offset relative to the **selected** base direction; it does not force Cockpit, reset FOV/response/distance, translate the eye or reopen the page. Clearly label this as “Recenter selected view.” Existing bound Cockpit remains the immediate traditional forward return. Wheel FOV changes update the current settings FOV; opening Views copies actual camera FOV and current preset/response, never a stale prior draft. No binding dictionary or action vocabulary changes.

## Look ownership, rearm and comfort

Live free look preserves the existing sensitivity and yaw/pitch clamps. **Cockpit and Panel retain their exact current expression and operation order**, `Basis(Vector3.UP,-look_angles.x)*Basis(Vector3.RIGHT,look_angles.y)*base_direction`, with their existing normalized base directions. Forward horizon uses that same expression on `(0,0,-1)`. Do not replace the traditional expressions with a mathematically equivalent reordered computation.

For each side view only, let `D` be its exact cardinal base direction. Use the side-local unit pitch axis `D.cross(Vector3.UP)`: Left window has axis `(0,0,-1)` and Right window has axis `(0,0,1)`. The exact new composition is `Basis(Vector3.UP,-look_angles.x)*Basis(D.cross(Vector3.UP),look_angles.y)*D`. The rightmost pitch acts first in the selected lookout frame; the existing signed yaw acts afterward. No normalization of the cardinal axis, world-horizon stabilization, eye rotation/translation or pitch-axis substitution is allowed. Positive `look_angles.y` raises either side direction toward aircraft-local +Y, and negative values lower it. The existing mouse/action-to-angle sign remains unchanged; this statement defines the camera angle, not a new input convention.

The following algebraic direction identities fix the signs before consumer outputs. Put `a=look_angles.x`, `b=look_angles.y`, `c=cos`, `s=sin`; all components are aircraft-local visual coordinates:

| Preset | Resulting direction |
|---|---|
| Forward horizon | `(s(a)*c(b), s(b), -c(a)*c(b))` |
| Left window | `(-c(a)*c(b), s(b), -s(a)*c(b))` |
| Right window | `(c(a)*c(b), s(b), s(a)*c(b))` |

At zero angles these are the three declared bases. At zero yaw, positive/negative pitch gives the same positive/negative Y component for both sides. At zero pitch, positive yaw gives negative Z for Left and positive Z for Right. These are exact real-arithmetic design identities, **not** executed Godot references or binary64 error budgets. Independent reference authoring must include zero, positive and negative pitch for both sides, positive/negative yaw, combined yaw/pitch, and aircraft-basis rotation before implementation. Releasing the current mapped `look_hold` still exposes the pointer without recentering or changing preset. Views entry needs visible-pointer mode and no active/queued pointer capture. Carry all real-release rearm state through the page; opening/Apply/Cancel cannot manufacture an up edge, clear held-button guards, release native brakes/starter, change held axes or bypass neutral/takeover. Resume remains the existing explicit validated menu action. Add Views to all existing modal/lifecycle guards rather than treating it as a second input owner.

For Chase/Orbit, `smooth` preserves the current offset-only filter `1-exp(-9*clamp(seconds,0,0.25))`; `immediate` uses the desired offset directly. Both add the offset to the **same current presented ownship translation** and use the existing corresponding look target. Never smooth aircraft translation separately, lag the camera against raw state, or filter native/maps/instruments. Interior views, paused draws, first draw and zero-time repeat preserve their existing no-filter-advance behavior; selecting a mode/response reseeds the offset before presentation, so no stale-mode blend is shown. Existing Orbit floor logic and coherent origin-rebase handling remain intact. No adjustable coefficients, shake, roll reduction or hidden time scale is added.

Preserve the **existing explicit traditional-mode transitions**: Cockpit/Panel versus Chase/Orbit still use their inherited cockpit/exterior visibility and panel-viewport update rules, and a changed `camera_mode` still uses ADR019's existing mode-dependent aid geometry/visibility. Selecting Panel may therefore change dock placement and the existing wind-card rule; selecting an exterior mode retains its existing panel-visible rule. This leaf does not redefine those inherited transitions as invariant or as a gaze-dependent layout fix. Any existing geometry-triggered pointer retirement remains ordered before geometry change under ADR017 and happens only when the existing conditions require it.

By contrast, choosing Cockpit/Forward horizon/Left window/Right window **within mode0**, changing FOV, free-looking, recentering or changing external response must not independently relocate, suppress/collapse or force aids visible, change requested manual visibility, or retire capture/bump input generation. In particular, same-mode direction/FOV adoption must not invoke inherited mode-reset side effects that would overwrite manual visibility. Apply occurs after the already-paused boundary, with no page-owned capture; it must not repeat pause/capture retirement merely to select a direction. Preserve fixed docks, engine controls, release/status accessibility and viewport-dependent geometry within that mode. No automatic dock mirror, HUD forcing or recenter-to-fit is permitted. #179 found actual deliberate-gaze occlusion; #192's mirror candidate failed. New side views are **not** a fix or a readability pass for those findings. The page states: “Side looks can move gauges out of view; flight aids keep their current positions. Use existing hide controls if needed.”

## Owned scope and acceptance

Consumer leaf: `app/camera/view_policy.gd`, `app/ui/camera/views_panel.gd`, focused `tests/camera/`. Coordinator serializes narrow Scene camera/menu/modal/lifecycle integration and its current staging/package/CI inputs. Preserve original camera proof functions and native fixtures; do not edit cockpit geometry, input schemas/Mapper, Facade, native, model, airport or aid layout. Independent tests own numerical/sign/reference cases and visual review.

Before consumers, freeze a small independently authored direction/composition/FOV/reset/filter packet; no output-fitted thresholds. Pure tests cover seven choices, strict types/copies, mirrored left/right signs, aircraft-rotated forward/left/right vectors, finite FOV bounds, reset/default/cycle/recenter and existing smoothing versus immediate for a declared sequence of presented poses. Include invalid values and idempotence.

Actual Scene checks exercise both profiles, all three supported starts and all seven choices at a verified paused boundary; Apply/Cancel/stale opening, focus/capture/lost-release/rearm, failed/successful restart, archive/review conflict and explicit Resume. Assert unchanged complete native readback/held controls/events/commands/tick/debt, mapper preset/capture/generation/edges and observed samples for page-only operations. Keep same-pose camera/body and origin-rebase/cadence checks. Do not compare a real pause/resume lifecycle call to a no-lifecycle baseline as if they were the same command history.

Minimum actual exported originals: seven presets at960x540,1920x1080,2560x1440, plus a1360x768 page/focus smoke check from original #26. Inspect three-size page text/focus/ancestor clipping and forward/left/right landmarks, unchanged eye/glazing, current-view/FOV label, Cancel, recenter and default restoration. Capture a small separate Chase/Orbit moving sequence for comfort response; static images cannot prove temporal phase. Preserve known gaze/aid overlap as labelled limits, not hidden passes. Normal source/PCK/native/replacement closure and current protected checks remain required; no new full physics campaign is justified solely by view presentation. No Cessna calibration, hardware comfort, human flight or phase acceptance is inferred from automated proof.
