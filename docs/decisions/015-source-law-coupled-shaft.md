# ADR015: Source-law coupled shaft midpoint v1

Status: Proposed contract for issue149; implementation begins only after independently reviewed protected merge. Source/math only; no new solver or reference-generator execution. This is a new numerical surrogate and a narrow engine chronology amendment. It is not an arithmetic repair to ADR014, aircraft calibration, physical friction validation or flight acceptance.

The preserved [native trial evidence](../evidence/P3/event-aware-shaft.md) failed three unchanged convergence checks. [Issue149](https://github.com/brettbergin/flight-simulator/issues/149) owns this correction and blocks [issue127](https://github.com/brettbergin/flight-simulator/issues/127). This contract extends [ADR010](010-original-piston-profile.md) and preserves [ADR014](014-event-aware-shaft.md). The [independent reference design](../evidence/P3/coupled-midpoint-reference-design.md) specifies the finite prospective test roster. Contract acceptance authorizes implementation work; numerical, runtime, aircraft and phase acceptance remain separate.

[ADR016](016-generated-native-build-identity.md) defines the subsequent generated expected native identity resource and versioned package evidence for issue149/127 integration. It changes no coupled law, arithmetic/physical criteria or profile default; runtime adoption still requires its separate gates.

## Decision and scope

Introduce closed method ID `event_aware_coupled_midpoint_v1` for the exact original piston/direct-drive/fixed-pitch engineering profile. Retain default native construction as `legacy_euler`, and retain `event_aware_constant_power_v1` exactly for historical reproduction and its immutable references. Do not change XML numbers, controls, public clocks, schedule, physical budgets, samples or exclusions. Do not switch the production profile default until the new contract, source, strict build, independent references and original coupled gates pass.

The new method integrates a source-derived speed-dependent torque law over each actual public interval. It uses implicit midpoint on angular speed, with algebraic localization of its declared shaft events. Thermodynamic state and engine operating mode are frozen once per public engine call. It does not run combustion, fuel, contacts or the airframe at internal ticks. The first implementation deliberately supports the exact original profile/table topology; future engines need a separately versioned descriptor/contract.

The necessary changes are explicit:

1. Starter torque uses the existing source starter torque/taper directly. The artificial conversion via `max(RPM,1)` is removed for the new method, with the existing 550/5252 conversion constants retained. This is removal of a numerical power floor, not a change to the model's starter-torque parameter.
2. Angular aerodynamic load uses the loaded dissipative CP table as a physical torque law, with no minimum 0.01 RPS power floor or low-RPS J substitution. Its limit at zero is zero torque. This changes the new angular surrogate; the old two methods keep their original floors.
3. The new shaft equation has no 0.01 rad/s torque divisor or 0.1 RPM negative-power clip. Constant-power friction has an explicitly constrained finite stop. Those old regularizations remain in both preserved methods. Existing pre-step thrust/moment evaluation remains once per public call; its legacy reaction-moment divisor is not silently removed by this shaft proposal.
4. At the public engine boundary, decide current combustion eligibility before computing Running-dependent FMEP. A current no-combustion condition must not compute a full tick of Running FMEP and then publish Running=false. This is an intentional chronology/model-surrogate amendment. The source's simplistic disappearance of Running FMEP after combustion stops remains a retained engineering approximation, not a validated friction model.

## Reaction moment compatibility

The preserved pre-step reaction path retains the original piston scalar-power clip: at pre-step engine `RPM<=0.1`, pass `max(pre_step_power_ftlb_per_s,0)` as reaction-moment input; otherwise pass the signed pre-step power. Evaluate `-Sense*reaction_power/max(0.01,omega0)` once in the existing propeller moment chronology. This prevents stopped-engine constant-friction power from becoming an artificial airframe reaction through the retained divisor. The source-derived shaft descriptor remains unclipped and independent of this moment-only scalar; it retains the finite-stop law specified below. Keep the original RPM comparison and both old-method source paths exact. Current-boundary mode selection still determines pre-step engine power. Verify zero negative-power reaction at stopped RPM and both sides of the original clip threshold separately from shaft integration.

## Public chronology and mode policy

For the new method only, FGPiston Calculate performs these operations once:

1. Read pre-step engine RPM and current native inputs. Update starter/cranking selection from actual held Starter. Evaluate MAP, airflow and fuel flow once from that RPM and current inputs, retaining the existing MAP integration formula and previous supplied-fuel/Starved state.
2. Evaluate startup/shutdown eligibility using this **current** fuel computation, current magnetos, pre-step RPM and the source's exact 0.8*IdleRPM and indicated-power 0.125 HP tests. A not-running engine can enter Running only under the existing strict RPM>0.8*IdleRPM rule, current fuel/spark and sufficient indicated power. A running engine leaves Running on current loss of fuel/spark, RPM<0.8*IdleRPM, or indicated power<0.125 HP. Equality retains the previous mode where the original test is strict. Compute prospective indicated power without calling Calculate/doFuelFlow again.
3. Freeze that resulting mode and thermodynamic frame. Compute the ordinary pre-step engine diagnostics/power once for that selected mode, including its appropriate FMEP. In cranking/not-running mode, pre-step starter power is torque times actual angular speed, hence zero at rest; it is not the old artificial 1 RPM power.
4. Evaluate pre-step thrust/moments once and advance the shaft through the descriptor below. Update thermal/oil state once under the documented public-step policy; no algebraic shaft trial changes these state variables. Keep a fixed source order in the eventual implementation/audit.
5. FGPropulsion consumes fuel once using its unchanged potential-flow sample and existing supplied-fuel chronology. Complete publication occurs only after the actual Run and existing checks succeed.

Running remains a **public-boundary mode**, held throughout the shaft solve. There is no intrastep combustion ignition, RPM-based Running flip, fuel availability refresh or repeated FMEP decision. A shaft crossing 480 RPM is observed by the next public engine call. This deliberately keeps the startup mode lag rather than inventing hypothetical combustion while the actual engine remains not-running. The original event-time envelopes remain the acceptance gate; continuous mode timing is not claimed. Current mixture cutoff is handled at its command boundary. Feed selection still affects availability through the existing ConsumeFuel/Starved lag; it must not be short-circuited by trusting the cockpit feed request.

Keeping one public fuel sample means fuel quadrature remains an operator split: speed-dependent angular work is integrated more accurately than the retained potential fuel-flow sample. This proposal does not claim exact combustion-energy/fuel conservation or overall second order. If the immutable fuel/coupled gates fail, preserve that failure and propose any required fuel-quadrature amendment separately; do not silently add one.

## Native interface

Add internal, non-wire types, with explicit backend units:

```cpp
enum class ShaftOperatingModeV1 { cranking, running, stopped };
struct ShaftPowerSegmentV1 {
  double c0_ftlb_per_s;
  double c1_ftlb;       // coefficient multiplying w [rad/s]
  double c2_ftlb_s;     // coefficient multiplying w^2
  double c3_ftlb_s2;    // coefficient multiplying w^3
  double lower_w_radps, upper_w_radps;
};
struct CoupledShaftFrameV1 {
  // Immutable, owned values; no executive/property/callback pointers.
  ShaftOperatingModeV1 mode;
  double pre_step_engine_rpm, h_s;
  double engine_c0_ftlb_per_s, engine_c1_ftlb, engine_c2_ftlb_s;
  double starter_torque_ftlb, starter_limit_w_radps;
  // The engine coefficients exclude starter output. Cranking adds the
  // separately declared starter torque/taper. Other modes ignore that term.
  // Propeller owns actual I, initial w, rho, V, D and verified CP topology.
};
struct CoupledShaftResultV1 {
  double final_w_radps;
  bool hold, reached_stop;
  unsigned cp_crossings, starter_taper_crossings;
  // Private diagnostics only until a separate public diagnostic contract.
};
```

FGPiston constructs a frame from once-computed current source state. FGPropeller combines it with immutable original CP-law coefficients and solves the scalar interval. Use the explicit internal overload `CalculateCoupled(const CoupledShaftFrameV1&, double pre_step_engine_power_ftlb_per_s)` so an old frame cannot persist in a property or setter across ticks. The frame belongs to the actual piston/propeller pair on the owning simulation thread; pre-step RPM and h must match the actual direct-drive propeller state/inputs. Only the actual selected new method may consume this frame. The old scalar Calculate call under the new method, or another engine without a matching frame, rejects visibly. No public arbitrary property, runtime method toggle or model-supplied executable callback is added.

Fresh session initialization verifies exact piston type, nonboosted engine, gear ratio 1, fixed 20-degree pitch, inertia 2 slug*ft2, diameter 6 ft, CP/Ct scaling 1, no Mach correction and the existing exact model/table provenance before selecting the method. These are the original profile's source parameters, not newly tuned values. Existing topology/model-pin checks remain. Unknown/other topology rejects before allocation/publication under the existing session policy. Future variants require a new supported descriptor contract rather than weakening this one.

## Source law and units

Let w>=0 be shaft angular speed [rad/s], I positive [slug*ft2], h actual public interval [s], n=w/(2*pi) [rev/s] and RPM=60*n. Backend radians are dimensionless. All coefficient derivations must name the actual source constants, including source unit conversions, rather than substituting rounded SI constants.

Freeze current MAP, PMEP, ambient temperature/pressure, volumetric-efficiency reduction, mixture/equivalence ratio, magnetos, StarterGain and selected mode. They are source values evaluated once, not fitted coefficients. With these held values the engine power is polynomial in w:

- Cranking/not-running: starter torque is `alpha*StarterTorque*StarterGain*max(0,1-w/w_starter)` where `alpha=550*60/(5252*2*pi)` and `w_starter=StarterRPM*2*pi/60`. Multiply that torque by w to obtain starter power; add source pumping power, linear in w. As in the source's cranking branch, the -StaticFriction_HP term is replaced by starter output, not added to it.
- Running: indicated combustion power is linear in w because source airflow and fuel flow are linear in RPM for the frozen thermodynamic frame. Derive its coefficient directly from displacement, reduced volumetric efficiency, manifold density, equivalence ratio/14.7, 2.2046, 3600, ISFC, the MIXTURE table and magneto drop. Source airflow is explicitly `swept_volume=displacement_SI*(RPM/60)/2`, so its angular coefficient is displacement_SI/(4*pi), independently of configured Cycles. Source pumping/FMEP power is `550*(PMEP+FMEP)*displacement_SI*RPM/(Cycles*22371)`. Keep those distinct constants exactly; do not replace airflow /2 with Cycles or replace Cycles*22371 with a newly rounded mechanical conversion. Do not divide sampled flow by w at zero. Constant static-friction power is `-550*StaticFriction_HP`. Source static FMEP contributes a linear loss and dynamic FMEP a quadratic loss. Pumping power is linear in w. Boost loss is absent in this exact nonboosted profile.
- Stopped/not-cranking: retain constant `-550*StaticFriction_HP` and linear source pumping power. Running FMEP remains absent, matching the explicitly retained source mode surrogate.

For aerodynamic load let `A=2*pi*V/D`, `L=rho*D^5/(2*pi)^3`, with axial aerodynamic V [ft/s], diameter D [ft] and density rho [slug/ft3]. The exact original table, with clamped ends, simplifies to:

- V<=0: CP=0.06 for all positive w.
- V>0 and w<=A/2: CP=0.02.
- V>0 and w>A/2: CP=0.06-0.02*A/w.

Thus aerodynamic power is either `0.06*L*w^3`, `0.02*L*w^3`, or `L*(0.06*w^3-0.02*A*w^2)`. It is nonnegative, and angular load torque tends to zero at rest. There is one finite CP breakpoint at A/2 when V>0; no generic CP-table solver is required. This angular load law is distinct from the preserved pre-step thrust path, whose existing J chronology is unchanged.

Every admitted original-source frame has c0<=0 and every aerodynamic segment has c3<=0. Positive constant-power input lies outside this production descriptor and its concavity proof; it is not an admissible synthetic production frame. Constant-power analytical references below mean loss (c0<0), with zero power handled separately. Concavity applies within each fixed segment; the starter-taper torque derivative jumps upward at its endpoint, so no global concavity proof may cross that knot.

Within a fixed CP/taper segment, net power is `N(w)=c0+c1*w+c2*w^2+c3*w^3`. For w>0 the torque law is `T(w)=N(w)/w` and `I*dw/dt=T(w)`. A cranking segment has c0=0, so its torque extends finitely to zero. A stopped segment has c0<0, which permits a finite constrained positive-zero stop only when its connected negative-drift branch reaches zero without an intervening equilibrium. Otherwise the equilibrium/noncrossing/domain rules below apply. After an admitted stop it stays at zero for the interval. With no starter, the solver may not create spontaneous rotation from zero. With starter, use the finite source torque at zero; nonpositive net starting torque remains at rest. No artificial speed or energy seed is allowed.

## Finite midpoint algorithm and root selection

For a segment starting at w0, define wm=(w0+w1)/2. The new discrete equation is:

`I*(w1-w0)*wm = dt*N(wm)`.

Equivalently, for wm>0, `I*(w1-w0)=dt*T(wm)`. It is implicit midpoint on the declared speed-dependent torque law. It is exact for constant torque and constant-power loss up to its admitted stop, and has local truncation error O(h^3) and global error O(h^2) for a fixed smooth frozen scalar law over a finite nonsingular interval with the usual bounded derivatives and stable continuation. This order statement does not apply across mode/source events or establish overall coupled engine order. It is **not** exact for arbitrary polynomial power or the fully coupled engine.

Implement bounded bracketed scalar bisection, never an arbitrary choice among cubic roots. The multiplied equation is cubic, but no general cubic formula is needed:

1. Validate method/frame/topology, all finite inputs, I>0, h>=0, w0>=0 and the independently audited arithmetic domain. h=0 preserves the original RPM bits with no assignment. Zero drift/equilibrium holds angular state exactly where admitted by the checked polynomial predicate. **When c0=0, cancel wm symbolically before root solving and use `I*(w1-w0)=dt*(c1+c2*wm+c3*wm^2)` directly, including w0=0.** Solving the multiplied energy equation at rest would otherwise introduce a spurious zero root. For positive starting torque, zero is not a candidate root. For zero/nonpositive starting torque at rest, hold without an artificial seed. Non-cranking rest with c0<0 is handled as constrained rest before any division.
2. Build at most the next CP and starter-taper endpoints in the actual drift direction. Do not cross a source equilibrium. For each fixed segment, T''(w)=2*c0/w^3+2*c3<=0; it is strictly negative if c0<0 or c3<0. Thus T' is nonincreasing. A nonconstant concave segment has at most two positive equilibria, with linear and constant cases handled explicitly. When c0=0, isolate equilibria of the canceled torque polynomial `Q(w)=c1+c2*w+c3*w^2`; never count the artificial zero of N=w*Q. When c0<0, isolate equilibria of N. For either polynomial use its effective highest nonzero degree d. Degree zero and nonzero has no equilibrium; an identically zero torque polynomial is hold. For d>=1, a finite Cauchy bound is `1+max_{i<d}|a_i/a_d|`, formed with checked outward ratios in the declared backend numeric units. No division by a zero c3 is allowed. Locate the unique possible torque maximum with the same effective-degree rule applied to Q' when c0=0, or to `-c0+c2*w^2+2*c3*w^3` otherwise; a constant derivative needs no root isolation. A zero derivative means constant torque. Use these classifications to bracket the nearest equilibrium in the drift direction within the current CP/taper segment. Pure constant nonzero torque uses its analytic linear update and finite negative-torque stop; pure constant-power loss uses its analytic squared-speed update and finite stop, with no equilibrium search. Those updates still obey event ordering, domain and roundoff gates. Bounds are mathematical bracketing values, never physical speed limits; overflow or a bound outside the audited arithmetic domain rejects. At most 64 bisections per bracket, with checked signs and adjacent-binary64 termination. Do not scan a generic table or take a guessed cubic root.
3. Define the continuation time map `H(x)=I*(x-w0)/T((x+w0)/2)` on the connected drift interval. Certify that it has the required strict sign/monotonicity before solving. Its derivative has the sign of `B=T(m)-(x-w0)*T'(m)/2`; multiplying B by positive m^2 gives the explicit degree-four expression `c0*x + (c1+c2*w0)*m^2 + c3*m^3*(2*w0-m)`. In positive drift, the concave tangent inequality gives `B>=T(w0)>0`, proving monotonicity directly. For negative drift, first use source coefficient signs where sufficient; otherwise use bounded outward interval/Bernstein sign certification with at most eight total algebraic splits (not depth-eight recursion). Split the widest remaining undecided interval, breaking ties toward lower speed. Exact endpoint zero may be symbolically factored; an inconclusive or nonmonotone certificate rejects. Strict monotonicity of H on the retained connected interval proves there is at most one admissible continuation; endpoint bracketing proves existence. Concavity proves the equilibrium classification, **not** universal uniqueness of every midpoint cubic. No root outside that certified interval is admissible. This is an explicit numerical admissibility test, not permission to select a convenient root, tune a state limit or silently fall back.
4. Solve H(x)=remaining h by at most 64 bisections in that certified connected interval. At a source CP/taper endpoint, compute its discrete event time by the same H, land exactly on the declared endpoint, consume that time and continue with the new polynomial. A source torque equilibrium is asymptotic for the continuous ODE, but **midpoint H(r) at an equilibrium r is generally finite**, since it evaluates torque at the midpoint between w0 and r. Reaching/crossing that equilibrium is prohibited in this contract: if h>=the finite H(r), reject rather than landing on it, crossing it, clamping or silently changing the method. Thus sufficiently large intervals near equilibrium may be outside this new method's numerical domain. Exact equilibrium at initial w0 is the separate hold case.
At an exact CP or starter-taper knot with nonzero drift, select the outgoing polynomial from that drift direction. Do not count or repeat a zero-time crossing. Both adjoining source expressions must agree at the knot within the independently audited coefficient enclosure. If the knot is also an exact initial torque equilibrium, hold; an incoming interval that would reach that equilibrium in finite discrete time rejects under rule 4. Knot/equilibrium ordering must be certified, not selected by rounded comparisons.

5. Zero is a permitted finite stop endpoint only if the connected negative-drift branch reaches it without an intervening equilibrium and either c0<0 (singular constant-power loss) or c0=0 with finite T(0)=c1<0. Evaluate H(0) by its finite one-sided expression. If remaining h reaches/exceeds the certified discrete stop time, write literal positive zero and retain it for the remainder. Pure constant-power loss gives exactly `I*w0^2/(2*abs(P))`; constant negative torque gives exactly `I*w0/abs(T)`. For varying torque it is the declared midpoint approximation, not an exact continuous stopping-time claim. If c0=c1=0 and torque tends to zero at rest, including pure linear/quadratic drag, zero is an asymptotic continuous equilibrium and is not a finite-stop endpoint: apply the finite-discrete-time equilibrium rejection rule even if H(0) has a finite limit. Reject if the branch lacks the unique continuation certificate.
6. At most one CP and one starter-taper crossing occur in a monotone interval, followed by at most one stop. Permit at most four completed algebraic segments. These are event segments of one shaft equation, not public ticks or repeated engine/fuel calls. Exhausted bounds, failed enclosure, unexpected event repeats, nonfinite evaluation or uncertain branch sign fail visibly and retain the last completed publication through the existing destroyed-executive policy.
7. Compute and check the final RPM conversion before assignment; retain signed-zero/no-op rules and explicit floating environment/FTZ/DAZ guards. A new operation/domain/roundoff audit is required. The previous helper's universal guarantees must not be copied onto this different algorithm.

Every 64-iteration bound is a work ceiling, not a claim that 64 iterations cover an arbitrary exponent range. A bracket must reach adjacent admitted binary64 endpoints with certified residual/output enclosure within the prospectively ratified arithmetic bound; otherwise reject. Outward arithmetic, exact-zero predicates and coefficient construction need their own source review. Event-time consumption must retain a checked compensated nonnegative remaining-time residual; uncertain subtraction/crossing order rejects rather than donating or losing time. No successful result may rely on an exhausted loop or an uncertified fallback.

The uniqueness certificate is material. Implicit midpoint with a negative constant-power term plus a positive torque can have multiple algebraic continuations near rest. Nearest-root guessing or unconditional zero clipping would introduce another hidden model. This proposal explicitly rejects uncertified intervals. Whether all required original-profile trials lie inside the admitted numerical domain is an open source/reference gate, not an assumption justified by the saved traces.

## Independent references and test gates

Bind both the chosen connected branch and residual. Include multiple-root/rejected cases; never choose the output closest to a native answer. Two independent precision levels must agree on the intended binary64 result before native execution is authorized.
3. Separately derive the continuous frozen-law solution by high-precision quadrature of `I*w/N(w)` between known events.
