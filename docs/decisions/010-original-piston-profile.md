# ADR 010: Opt-in original piston and fixed-pitch prototype

Status: proposed contract; normative after the checked contract PR for [#122](https://github.com/brettbergin/flight-simulator/issues/122) merges. Consumers also require a checked, byte-pinned original model/parameter/reference package before implementation. This is a bounded engineering fallback allowed by [P3](../phases/p3-complete-circuit.md), not acceptance of the C172S configuration, [#28](https://github.com/brettbergin/flight-simulator/issues/28), [#29](https://github.com/brettbergin/flight-simulator/issues/29), or a phase gate. Supports REAL-013, REAL-014, PRD-004 and PRD-010. Basis: [v1 contracts](../contracts.md), [ADR006](006-interactive-prototype.md), [ADR007](007-sim-loop-facade.md), [ADR008](008-input-presets.md) and [ADR009](009-cockpit-readings.md).

## Outcome and identity

Provide a selectable **Original piston prototype — cold engine** with deliberate fuel, mixture, ignition and starter controls, native shaft readings and causal shutdown. The starter has an idealized external supply. This is not a cold-and-dark electrical simulation, manufacturer checklist, C172S engine or sensed instrument. Hot/flooded starts, oil indications, battery/master/alternator, pumps/vents, source-specific magneto-drop limits, failures and calibrated performance remain separate work.

Keep the direct-thrust profile, old inventories, named starts, command rejection and historical proofs unchanged. New model identity has exactly `id:"original-piston-prop-v1",version:"0.1.0-prototype",backend_model:"original-piston-prop"`. Its separate package resides at `native/fdm_jsbsim/models/original-piston-prop/`; a model leaf must freeze its original XML, inventory, parameter ledger, notices and independent numerical references before runtime consumers. Attribution covers inherited project-original airframe/aerodynamics/gear. Vendor aircraft/engine XML and restricted manufacturer data cannot substitute for original authorship.

Native construction selects a closed profile enum defaulting to the legacy profile. [ADR013](013-steady-wind-starts.md) deployed wind as the third argument; [ADR014](014-event-aware-shaft.md) proposes the compatible fourth profile selector: `open_session(model_root:String,named_start:String,wind_profile:Variant="calm",profile_id:Variant="original-interactive-prototype")`. The bridge retains its six operations and explicitly registers both trailing defaults, preserving actual two/three-argument callers. Facade `start` uses the same order/defaults and actual String admission. Reject unknown profiles, wrong roots/hashes/versions and unsupported `(profile_id,named_start,wind_profile)` pairs before closing a prior session, allocation or publication; no inference from directory names. Selection changes only through confirmed close/join and fresh construction. Reset retains the accepted profile/wind and admits only its supported recipe. The original three-argument profile proposal is superseded only after the checked ADR014 amendment merges.

The new profile admits only `piston-cold-ground`: the same prepared plane/world hash as ADR006, runtime120Hz/seed42, CG ellipsoid height1.05m, zero velocity/pitch, full brakes, throttle0, mixture0, ignition left/right false, starter false, feed true and100kg initial usable fuel in one original tank. These are explicit authored engineering choices. Running-ground and airborne recipes are deferred. Validate installed piston/propeller types, direct drive ratio1, fixed pitch, feed index and finite state against the new inventory. Do not call trim, steady-state, `InitRunning`, inject RPM, advance hidden positive ticks or mark IC engines running. `RunIC` can indirectly start engines if its IC flag requests it; prohibit that path and verify tick0 shaft0/Running=false after explicit switch/mixture initialization. Fresh executive construction is mandatory; a warm backend reset is not a cold start.

## Commands, fuel and native ownership

Keep ControlCommand/v1, AircraftSnapshot/v1, OperationalEvent/v1 and SessionControl/v1 unchanged. Complete PilotAxes payloads replace axes only. The old profile still rejects all system controls and mixture other than1. The new profile admits finite mixture0..1 through axes only; no competing numeric system alias. Four system IDs admit actual booleans only:

| ID | Native mapping |
|---|---|
| engine.ignition_left | Held bit0 of the final magneto mask |
| engine.ignition_right | Held bit1 of the final magneto mask |
| engine.starter | Actual backend starter request, with idealized supply |
| fuel.feed | Selected state of the one authored feed tank |

Numeric values for these IDs, unsupported IDs, nonpilot authority/source, wrong session, invalid sequence/tick/capacity or incompatible profile reject before consuming command sequence. System commands target exactly `current completed tick+1` (the next unexecuted tick), with checked uint64 arithmetic; speculative later system ticks reject, preventing future starter requests from surviving recovery. The pilot path uses `pilot.controls`, authority pilot and unassisted metadata. Existing trusted-host registration and core ordering remain; this slice admits no automatic avionics/scenario/instructor system controller. No governor, prop pitch, feather/reverse, carb heat, refill or arbitrary property API.

Apply the accepted `(tick,authority,source_id,sequence)` order, constructing candidate axes and separate four-bit system state. Apply their final values once before one real solver step; no intermediate switch change runs the engine. Set both declared FCS command/position mappings for throttle/mixture. Commit held values, queue removal and publication only after all existing world/callback/clock/readback guards succeed. Fault after mutation destroys the executive and retains the last completed publication; partly changed state cannot continue. Pause alone changes no held controls; close/reset preserves joined-worker ownership.

Fuel mass uses actual tank contents. Pinned backend consumption occurs after engine calculation; shortage/starvation can affect a subsequent engine calculation. Final partial-tank draw may clamp while requested flow/cumulative FuelUsed exceeds actual drained mass. MassBalance runs before that draw, so published mass/CG and post-draw fuel can reflect different solver stages. Declare and test this chronology without recomputing physics in UI or claiming immediate shutdown. Freeze a bounded depletion discrepancy and lag criterion before observing tests, or resolve fuel admission in a separately reviewed native contract before shipping. Conservation checks compare actual tank decrement with actual supplied fuel, not requested backend flow at exhaustion. No negative fuel or hidden refill is permitted.

## Public observations and presentation

Readback retains ADR007's exact keys; `model_identity` has the same three closed keys and accepts only the two reviewed profile identities. New native source fingerprint and per-profile inventory hashes must be accepted explicitly after source/package proof; do not loosen legacy identity, mixture or shape checks globally. Canonical geometry/world/origin/pacing semantics stay unchanged. All systems below have unique IDs, actual completed-tick values and existing v1 quantities; invalid/missing sources show unavailable.

| ID | Wire quantity | Meaning |
|---|---|---|
| fuel.total | kg | Actual single-tank contents |
| engine.throttle | fraction | Applied native-held throttle |
| engine.mixture | fraction | Applied native mixture position, matching held axes |
| propeller.angular_speed | radps | Actual post-propeller-step shaft RPM multiplied by2π/60 |
| engine.running | bool | Actual backend combustion Running flag |
| engine.ignition_left / engine.ignition_right | bool | Actual magneto selection mask bits |
| engine.starter | bool | Actual starter request; no electrical energization claim |
| fuel.feed | bool | Actual tank selection |
| engine.starved | bool | Actual backend starvation flag under the documented chronology |

Piston cached RPM is read before propeller integration; do not publish it as the completed shaft state. Forces remain the backend's actual forces, not recomputed from publication RPM. Direct drive ratio1 is the only basis for equating shaft rates. Internal test traces may carry power, torque and requested/supplied fuel flow with explicit units; public W, N·m or kg/s requires a later unit/version contract, never a mislabeled existing quantity.

A separate engine-status producer validates the full copied, identity-qualified Readback and required system type/quantity/validity. It never infers RPM/running from throttle or switch intent. Display RPM converts rad/s by60/(2π) only at the drawing boundary. Ordinary pause is fixed current truth; terminal/closed copies remain RETAINED; malformed/empty input clears numeric state. ADR009's nine channels and frozen formulas remain unchanged, with explicit new-profile identity admission. Sensed InstrumentSnapshot channels remain separate.

New-profile prop animation uses actual finite shaft rate, including stopped/coasting/cranking states. Combustion audio depends on native Running/shaft state; throttle alone cannot create an engine tone. These are original authored presentation cues, not calibrated recordings. Preserve legacy presentation/proofs. Engine status and controls remain usable alongside existing views/scan, without camera, map, contact or authoritative-state smoothing.

## Exact input and facade extension

InputPreset/v1 and its configure/sample/suspend results remain unchanged. InputPreset/v2 has exactly nine top-level keys: the existing `type,version,name,devices,axes,actions` plus `profile,capability_revision,systems`. `type` remains InputPreset, `version` is2, profile is the exact new three-key identity above and capability_revision is exactly `piston-controls-v1`. ADR008 file/text/device/source/count bounds apply. Exactly eight axes use the existing binding shapes; mixture now admits fixed/key_pair/unsigned joy_axis in0..1, with no return-to-start digital mixture. Other axes/actions keep their current semantics.

`systems` contains exactly four unique bindings `{id:String,kind:String,sources:Array[Source]}` for the four command IDs above. Starter kind is `momentary`; ignition/feed kinds are `toggle`. Each has1..4 ADR008 physical-key/observed joy-button/persistent mouse-button sources. Transient wheel buttons4..7 are prohibited; mouse buttons1/2/3/8/9 are persistent. Unknown kinds/IDs, fixed starter values and timed pulses reject. Bound sources participate in cross-axis/action/system conflict checks; no physical control may trigger an engine source and another axis/action/system, including overlapping key aliases. Escape remains reserved. This is an explicit new-profile capability table, not arbitrary capabilities trusted from imported data.

| Method/value | Exact extension |
|---|---|
| Mapper.configure_v2 | `(preset:Dictionary,held_axes:Dictionary,start_axes:Dictionary,initial_raw:Dictionary,profile:Dictionary,held_systems:Dictionary)->{ok:bool,error:String}`. Validate/deep-copy all inputs atomically. Profile comes from verified Readback; held_systems has exactly the four capability-ID keys and actual bool values copied from valid native snapshot systems. | Mapper.suspend_v2 | `(reason:String,held_axes:Dictionary,held_systems:Dictionary)->{ok:bool,error:String}`. Toggle intent flips once on a rising edge of the OR of all aliases; simultaneous aliases coalesce and a held alias prevents repeats. Starter intent is the OR of held persistent aliases. Configure/suspend accept only explicit verified held feedback; sampling does not infer controls from engine behavior. Suspended sample(raw,0) shows copied actual held axes/systems with no actions, toggles, filters or slewing; nonzero elapsed rejects. It must not relabel a paused native starter-true request false.

Mode-aware resume_confirmed requires all bound engine sources released plus ADR008's existing centered/released/generation gates and primes all edges. Its next live starter intent is explicitly false. Absolute mixture joins throttle/trim takeover within0.03; until matched, retain copied held mixture. Digital mixture begins at actual held0, never automatically full rich. Removal/focus/invalid raw pauses before another solver advance. Controller then suspends/rearms both complete intent sets; explicit Resume is still required. The initiating UI key/click remains exempt only if it is not itself an engine source. No automatic cranking on reconnect.

Facade emission occurs only at its next due boundary: changed axes first, then changed system IDs in the fixed order `engine.ignition_left,engine.ignition_right,engine.starter,fuel.feed`. Use one shared checked uint64 pilot sequence lane, same next tick/source/authority/unassisted metadata, reserving all required increments before any submit. Old-profile payload/rejection behavior stays exact. Pending local starter-true intent is removed before recovery; recorded starter=false must be admitted before the first resumed Run when the paused native request was true. Failed release/admission is terminal with zero subsequent ticks, not a success-shaped resume.

Each submit remains separately admitted. Do not claim an atomic five-command backend transaction. If a later acceptance/reply fails, retain the honest accepted prefix, perform no Run, close/join and retain last completed truth. Verify actual applied payloads/types/IDs/sequence/pending identity; update expected held axes only for axes records and expected switches only for their IDs. Completed native snapshot must match final applied held selections. Model/type/shape mismatch fails closed. All accepted system requests target the immediate boundary, so stale future requests cannot supersede the recovery false. Origin/pacing/command observation rules remain ADR007.

Explicit v1 import into this profile produces only a migration draft: copied old bindings, fixed-full-rich mixture and unbound engine controls visibly identified. Draft is not valid active v2; the user selects nonconflicting bindings and explicitly Apply. Export is v2 and cannot silently replace a v1 file or activate on import. Guest explicit JSON interchange and future SQLite profile ownership remain ADR004/008. Selected profile/preset changes require native pause, complete source observation and fresh-session profile selection.

Original keyboard v2 defaults retain existing flight/view bindings, use F8/F9 for left/right ignition, F10 for feed toggle, held F12 for starter and comma/period for mixture decrease/increase at0.25/s. Verify these physical-key aliases are unbound before activation; reject conflicts rather than silently overriding. Controls exposes engine bindings and native-held/pending values. No live cockpit click bypasses the mapper or overlaps remapped flight input. Profile selection starts paused; UI explicitly labels idealized starter supply and the engineering interaction.

For the new profile, start_ground requests piston-cold-ground. Preserved start_airborne bindings report an unsupported recipe without closing the current session or silently selecting another model. Validate the profile/recipe pair before destructive reset work. Existing two legacy recipes retain their previous behavior.

`EngineStatus.from_readback(Variant)->Dictionary` returns the same six top-level keys as ReadingSet: session_id,tick,state,native_truth,readings,error, with native_truth=true. State/identity/historical/error rules match ADR009. Its readings dictionary contains exactly the ten unique system IDs in the public table above (the two ignition IDs are separate); each channel has exactly `value:float|bool|null,unit:String,valid:bool,error:String`. Unit equals its fixed wire quantity; bool quantities require actual bool, all others finite binary64. Missing/unavailable individual systems return null/invalid with reason; malformed entire Readback, unsupported profile or contradictory identities/flags invalidates the entire set and clears values. No omitted channel, stale fallback or implicit zero. Owned copies and full wire validation are mandatory. Drawing owns RPM conversion and bounded readable formatting; physical state never uses these presentation values.

## Pinned backend mechanism and reference gates

Basis is inspected JSBSim1.3.1 commit `3b25f25e49b42d0489c04ac805674fc1450ca579`, locked archive SHA256 `df57467a831cfa3ee3cadcb98d8291ce56bb11976e35dd9e93c94201ff1420d5`. Source behavior is evidence about a generic backend, not aircraft calibration. Relevant primary code: [FGPiston](https://github.com/JSBSim-Team/jsbsim/blob/3b25f25e49b42d0489c04ac805674fc1450ca579/src/models/propulsion/FGPiston.cpp), [FGPropeller](https://github.com/JSBSim-Team/jsbsim/blob/3b25f25e49b42d0489c04ac805674fc1450ca579/src/models/propulsion/FGPropeller.cpp), [FGPropulsion](https://github.com/JSBSim-Team/jsbsim/blob/3b25f25e49b42d0489c04ac805674fc1450ca579/src/models/FGPropulsion.cpp), [FGTank](https://github.com/JSBSim-Team/jsbsim/blob/3b25f25e49b42d0489c04ac805674fc1450ca579/src/models/propulsion/FGTank.cpp), and [RunIC](https://github.com/JSBSim-Team/jsbsim/blob/3b25f25e49b42d0489c04ac805674fc1450ca579/src/FGFDMExec.cpp).

The model/reference leaf records every effective piston/prop parameter as original authored, retained library default or explicitly derived, with units, source/revision/hash, bounds and uncertainty. Freeze positive finite inertia/diameter, ratio1, fixed min=max pitch and explicit constspeed0; maxrpm can otherwise activate governor behavior. CT/CP tables require original authorship, complete domain/interpolation/extrapolation and independent references. At positive shaft rate n, J=V/(nD), thrust=CT·ρ·n²·D⁴ and load power=CP·ρ·n³·D⁵. The near-zero backend branch uses V/D and a rate floor; test it separately as a startup approximation, not ordinary dimensionless advance ratio. Discrete angular-momentum/energy references follow the actual update order rather than asserting exact continuous energy conservation.

Explicit source-unit references must cover raw starter-torque ft·lbf, effective prop inertia conversion, backend approximate fuel kg/lb constants and exact public SI conversion. Freeze startup/mixture/starter formulas, magneto and torque/rotation signs, phase chronology and numerical budgets before runtime output. No retuned goldens, measured BSFC claim, prop slipstream/P-factor/windmill/reverse/stall fidelity inference or copied manufacturer table.
