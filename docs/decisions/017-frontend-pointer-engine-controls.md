# ADR017: Transient pointer operation of original engine controls

Status: accepted under [#157](https://github.com/brettbergin/flight-simulator/issues/157) by [PR161](https://github.com/brettbergin/flight-simulator/pull/161), merged as `3cd3eaf79438e3802705b4bf8177f9b3bf59893e`; consumer [#158](https://github.com/brettbergin/flight-simulator/issues/158). Qualified #127 delivery merged before the contract. Depends on accepted ADR007/008/009/010 and qualified #127 delivery; supports #21/#23, REAL-019/021, PRD-015 and UX-009/010/011/012/013. Does not close their broad hardware, source, interaction or phase acceptance requirements.

## Decision

Add a small visible engine-control strip for `original-piston-prop-v1`. It admits only throttle, mixture, engine.ignition_left, engine.ignition_right, fuel.feed and engine.starter. Operate only while the matching identity-qualified facade is live/unpaused, the mapper is v2/live, the pointer is visible, and no menu/review/archive/route/calibration/discard/modal/input-fault owner is active. Paused controls show actual state but do not change it or implicitly resume.

The mapper remains the sole local pilot-intent owner. Pointer requests are transient main-thread copied data. The strip never calls native or Facade, mutates a readback, synthesizes key events or derives physics. Host continues its ordinary one complete axes+four-bool `Facade.set_pilot_intent` path before wall advancement, with unchanged next-tick sequence reservation/order, source pilot.controls and unassisted provenance. No InputPreset/v1/v2 field, native/wire schema, aircraft model or new preset action is introduced. Pointer ownership is never saved.

## Live UI routing and deliberate pointer access

GUI handled events remain visible to `Input` polling. Do not strip buttons from Raw, suppress validity checks or reset physical edges to make a panel click appear harmless.

Before any raw sample/filter mutation, the host examines a panel press against the complete active preset. Its initiating persistent button must be one of1,2,3,8,9 and absent from every active axis/action/system source, including look_hold, brakes, idle, engine and lifecycle actions. Current axis source kinds contain no mouse button, but the scan includes that category rather than assuming future authority. A bound-button press within a visible, live, profile-eligible engine hit region rejects the gesture and requests the normal input pause before sample/submission/Run; copied native-held state remains unchanged. Hit-region eligibility is independent of binding permission: rendering the target disabled solely because primary left is already bound cannot bypass this preflight pause or let the physical action double-fire. Hidden, legacy, retained, nonlive or modal-owned controls remain noninteractive without capture and retain the existing physical-input semantics. Show the specific conflicting binding and release/remap guidance. The preset is not edited automatically. Mouse wheel is not an engine gesture source.

While mouse look is captured, the strip is noninteractive. A visible hint names the current look_hold binding: release it to expose the pointer. Its deliberate release returns visible-pointer mode on the next ordinary host input boundary, preserving camera mode and look angles; no recenter/new action/pause is required solely to expose the pointer. A new look_hold activation during any panel capture conflicts and pauses before state mutation rather than recapturing mid-drag. Existing Escape and keyboard operation remain available.

An eligible unbound UI button cannot simultaneously trigger a mapped flight/view/system action. Clicking elsewhere keeps existing behavior. Retained/invalid/legacy displays are noninteractive; no cold commands are emitted. Hidden/noninteractive controls cannot acquire capture.

## Axis ownership and physical-source interaction

Exactly one pointer capture exists. Capture claims only its lever's local requested value; other axis owners continue normally. Validate every bound device, observed control and pinned generation even when one of its axes is temporarily pointer-owned. Disconnect/invalid Raw still pauses before any solver advancement.

Fixed-bound throttle or mixture is explicitly disabled in the strip, with its fixed binding/value and reason shown. Do not silently create a manual latch that defeats a fixed preset. Keyboard rate levers can start dragging only when both positive and negative alias sets are released. A thumb press seeds the current mapper-requested value, not potentially older native-held feedback. A track press is a deliberate normalized jump; it is represented explicitly by begin's requested value. Keep actual-held marker separate in both cases.

While a key_pair lever is captured, any positive or negative physical alias press—including opposing aliases whose net direction would be zero—is a same-control conflict and pauses before all mutation. Digital continuation after release starts from the final requested value with only future sample elapsed time, preserving the existing rate/clamp rule. Do not integrate the release interval once under pointer and again under keys.

While a joy_axis lever is captured, its physical influence is suspended for that target only; unequal hardware positions, movement and noise are not conflicts. Raw/device validity remains checked. Release retains the final requested value and arms only that target's existing .03 mapped-value takeover. Existing calibration, reversal, deadzone, gain and slew apply when hardware resumes; other axis takeover state is untouched. No last-moved-device rule.

Idle activation while throttle is captured conflicts and pauses before idle or pointer mutation. A pending one-shot throttle pointer change and same-interval idle activation also conflict. Other existing flight overrides keep their semantics. Different controls may change together.

## Desired switch values and momentary starter

Ignition/feed clicks enqueue a desired bool computed once from copied mapper-requested state at press. Notifications for the same gesture repeat that desired value, never recompute a toggle. The mapper derives physical toggle candidates from OR-alias rising edges and pre-sample intents. Agreeing pointer/physical desired bools coalesce; opposite values conflict before mutation. A held physical toggle alias without a new edge is not a second toggle. Changes to different systems are compatible.

Pointer starter capture begins only when all physical starter aliases are released. During capture its held contribution supplies true; a physical starter press conflicts and pauses. Outside pointer capture, physical starter keeps unchanged momentary OR-alias behavior. Pointer up, leaving the held target, capture loss, focus loss, modal entry, pause or fault ends the contribution and requires observed real button release followed by a fresh press. Re-entry while still held does not restart. Lever drags may continue outside their target until up; do not accidentally apply starter's leave rule to a lever.

Release clears local pointer contribution only. It does not fabricate a false paused publication or clear unrelated ignition/feed values. If native starter was true at pause, keep its actual indicator true until the accepted Facade recovery release completes. Resume requires physical engine aliases released and all pointer rearm buttons observed released. Existing starter=false admission before the first resumed Run remains authoritative. No timer, automatic retry, toggle starter or invented solver pulse. Down and up before any due boundary may legitimately yield no true native starter tick.

## Closed transient app seam

The following is an app interface only, not a saved preset or simulation schema. Existing configure/sample/suspend results stay unchanged (legacy six sample keys; piston seven with systems). Methods require the main thread and return owned copies.

| Mapper method | Contract |
|---|---|
| `bind_pointer_session(session_id:String)->{ok:bool,error:String}` | Called after successful v2 configure while suspended, using the already qualified facade session ID and existing session-ID validation. Bind only that session; no arbitrary profile assertion. Invalid call leaves pointer operation disabled. A fresh accepted binding/configuration invalidates captures. |
| `pointer_view()->Dictionary` | Exactly `session_id:String|null,generation:int,last_token:int,capture:Dictionary|null,requested_axes:Dictionary|null,requested_systems:Dictionary|null,rearm_buttons:Array[int],error:String`. Axes/systems are copied current mapper intent only; not actual native truth. A capture has exactly `token:int,control:String,button:int`. Empty/unconfigured returns null identities/values and no capture. Panel combines this with separately admitted actual EngineStatus/held feedback. |
| `queue_pointer(gesture:Dictionary)->{ok:bool,error:String}` | Validate/deep-copy bounded event metadata and stage it, or return accepted-inert success for the explicitly idempotent/obsolete no-ops below; success never means submitted or applied. Complete raw eligibility/conflict checks occur atomically in the next ordinary sample. A queue error is a host input fault requiring normal pause before Run. |
| `invalidate_pointer(reason:String)->void` | Discard staged gestures, retire capture, increment generation and latch its initiating button until complete Raw confirms release. Host calls on focus/modal/widget lifecycle transitions; configure/suspend/terminal paths do so internally. Does not poll Input, submit controls or change native truth. |

Gesture has exactly `session_id:String,generation:int,token:int,control:String,phase:String,button:int,value:float|bool|null`. Session matches the binding; control is one of the six listed IDs. Phase is begin/move/end/cancel. Integers are actual ints, generation0..2147483647, token1..2147483647, button one of the five persistent codes. No timestamp, native tick, sequence, object, path, arbitrary method or source identity is accepted.

Begin token is last_token+1. The panel caches it for that physical gesture; exact repeated begin notifications with the same token/content are idempotent. No second capture may begin until its predecessor's terminal event is consumed by a successful sample or lifecycle invalidation. Axis begin/move/end has actual finite float value0..1. Switch begin has actual bool; move is invalid; end has null and retires capture without changing the chosen desired bool. Starter begin has true, end false; move is invalid. Cancel has null for any control, discards that capture's unsampled lever/switch changes and terminates starter contribution without reverting already sampled lever/switch intent. Any completed lever value is its final requested value. A queued release consumes the final axis value before returning ownership.

Only one active capture and at most16 pending events exist. Coalesce pending moves for that capture to the latest finite value; do not coalesce begins, desired switch changes or terminal events. Reserve room for end/cancel: overflow rejects and pauses, but retires the local capture through lifecycle invalidation rather than leaving a held starter. A terminal event dominates later motion for that token; an exact duplicate terminal notification returns accepted-inert success. Obsolete terminal notifications follow the explicit rule below and can never retire a newer capture; stale nonterminal requests remain errors requiring normal host pause. No wrap/reuse: generation/token exhaustion disables pointer controls with an explicit fresh-attempt error. Fresh mapper lifetime may reset counters only with a fresh session identity.

After complete closed-shape/type/control/value and session-ID-syntax validation, an end/cancel notification for a nonmatching valid session, an older generation, or an older token returns `{ok:true,error:""}` as an accepted-inert obsolete no-op. It is not queued and changes no capture, rearm, counter, intent, filter or edge state; the host must not pause because of this successful obsolete notification. Evaluate session/generation obsolescence before comparing counters from a different identity: future generation/token within the current applicable identity, malformed metadata, or a mismatch with the current capture remains an error and requires normal pause. Exact duplicate terminal notifications are likewise accepted-inert. Old begin/move requests are not covered by this terminal exception and retain error/pause behavior. This distinction prevents an old release from indirectly retiring a newer capture through the normal queue-error pause path.

Configuration Apply, pause/resume boundary, focus loss, modal entry, reset/profile change, terminal fault and widget retirement invalidate capture/generation. Repeated idle frames are not new transitions and must not consume generations. Old release cannot retire a newer starter capture. If a button remains physically down after invalidation, binding/rebuilding the UI does not rearm it: the host observes release through unchanged complete Raw and then permits only a fresh press.

## Atomic sampling and chronology

Before `_values`, physical/system action edges, brake latch, takeover or pointer-requested state mutate, validate the complete Raw and queued pointer set, full device observations/pins, current identity/eligibility and all conflicts. Stage the whole candidate and commit only if all checks succeed; calling current `_sample_axes` first and rejecting pointer events afterward is forbidden. Rejection returns the existing failure-shaped sample (axes/systems null, no actions) and leaves all those intent/filter fields unchanged. Capture-retirement metadata may be cleared by the subsequent normal host pause, which seeds suspend from actual held feedback. No accepted-prefix physical sample is hidden.

The host preflights bound panel-button routing before mapper sampling, processes the successful ordinary action set, then rechecks same facade/session and live/no-modal eligibility before the unchanged full intent submission/advance. An action that changes session/pause/modal state invalidates pending pointer work; it cannot apply to the next session. Ordinary suspended diagnostics return actual copied held axes/systems and never execute queued pointer gestures. The panel owns a local unsampled gesture preview and queued label, cleared when its terminal event is consumed or capture is invalidated. The pointer_view requested_axes/requested_systems fields describe only the last successfully sampled mapper intent, never unsampled preview; no new view field is added. Preview, sampled requested intent and actual feedback remain distinct; only copied native publication updates the actual marker/RPM/running display. Missing/retained/terminal channels remain honest and disabled.

## Adopted frontend resource and UI decisions

Use the four mapper method names and exact copied shapes above, with at most16 pending events and one active capture. These are frontend resource limits, not aircraft parameters. The first visible strip uses only primary left button1; it does not automatically remap a preset. The closed validator still recognizes persistent buttons1,2,3,8,9 as specified for metadata/rearm. If primary left is bound anywhere in the active preset, explain the conflict and require deliberate release/remap rather than silently consuming a flight action.

Integrate one compact strip beside the existing native engine feedback, with an explicit expand/collapse affordance that keeps the existing Controls/help and primary instrument/runway access. Collapse/retirement invalidates capture. The960x540 minimum and1080p/1440p evidence determine final spacing; no source-supported aircraft geometry is implied.

Cancel ends capture and discards that gesture's unsampled changes, while retaining already accepted mapper lever/switch intent. It does not revert a sampled value or invent native truth. The separate ordinary pause/suspend path discards unadmitted work and reseeds from actual held feedback. No remaining method/cap/button/cancel choice is delegated to a consumer.
