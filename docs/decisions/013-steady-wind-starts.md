# ADR 013: Synthetic steady-wind starts and native-truth cues

Date: 2026-10-04. Status: proposed; consumers wait for the reviewed contract merge and coordinator dispatch. Contract issue [#140](https://github.com/brettbergin/flight-simulator/issues/140). This P2 engineering prerequisite partially supports PRD-007/008, REAL-011 and SAFE-022; it does not complete weather lessons or those requirements. Basis: accepted [ADR006](006-interactive-prototype.md), [ADR007](007-sim-loop-facade.md), [ADR009](009-cockpit-readings.md), [ADR011](011-observed-flight-review.md) and [ADR012](012-observed-review-interchange.md). The unaccepted piston consumer #127 remains separate.

## Outcome and limits

The player can choose **Calm**, **From north**, **From west** or **From east** for a fresh ground-ready or airborne-prepared flight. Conditions are modest original synthetic engineering inputs, not real weather, a C172 crosswind limit, an appropriate-flight recommendation or a handling qualification. Actual native wind drives a compact wind cue and a direction-only windsock; choosing a draft cannot change the current airplane.

Extend only ADR006's zero-wind initialization constraint. Preserve both named starts, original-interactive-prototype version 0.1.0-prototype, its pinned XML bytes/rights, prepared surface digest `04bff5a0bcf3509990f6276b2548a28268f57fc96d218a7ca51cab1990ec1ff5`, anchor, gear/contact authority, seed 42, dry ISA atmosphere, runtime 120 Hz and existing controls/clock/coverage bounds. Turbulence and gusts remain zero. There is no live weather setter, time-varying field, shear, METAR, pressure/temperature chooser, sensor emulation, scored lesson or physics feedback aid. Existing tolerances and convergence budgets are unchanged.

This prepares bounded children of [#44 WEATHER-PROFILES](https://github.com/brettbergin/flight-simulator/issues/44) and [#22 SYNTHETIC-AIRFIELD](https://github.com/brettbergin/flight-simulator/issues/22). Their broader dependencies and acceptance remain open. [#41 REGIONAL-AIRPORTS](https://github.com/brettbergin/flight-simulator/issues/41) still requires P3, world provenance and terrain streaming; this synthetic leaf supplies no real airport data. Contract merge alone accepts no consumer, phase, aircraft, hardware, pilot or training credit.

## Closed wind selection

Use exactly these case-sensitive ASCII String IDs. Omitted selection means `calm`; it never means the last menu draft. No arbitrary vector, speed, bearing, dictionary, nullable value, StringName, coercion or provider URL is admitted through this selection seam.

| ID / displayed choice | Native toward-NED vector (north, east, down), m/s | Wind-from true bearing | RWY36 northbound interpretation | RWY18 southbound interpretation |
|---|---|---|---|---|
| `calm` / Calm | `(0,0,0)` | Unavailable | Calm | Calm |
| `from-north` / From north | `(-5,0,0)` | 000 degrees true | Headwind | Tailwind |
| `from-west` / From west | `(0,5,0)` | 270 degrees true | From left | From right |
| `from-east` / From east | `(0,-5,0)` | 090 degrees true | From right | From left |

Five m/s is an authored exact SI choice, approximately 9.7 kt in the display. It is not claimed to be an exact 10 kt input. Headwind/left/right labels refer to the stated runway direction, not the aircraft's current heading; selecting runway18 on the locator does not rotate or replace the wind. Do not call the north preset a headwind without that runway qualifier.

The prototype holds these components constant in the local NED field throughout a session. It is not a constant ECEF vector or a model of altitude/terrain-dependent weather. Vertical wind is zero. The selected field has no mutable runtime control and remains separate from the unchanged stationary ground-plane identity.

## Native and facade extension

Add native `enum class SteadyWindProfile { calm, from_north, from_west, from_east }` and `Config::wind_profile`, defaulting to `calm`. One checked native mapping produces the table's vector; invalid enum values reject before solver allocation. Do not independently accept an enum and a contradictory numeric vector. Existing Config recipe checks remain, including ground trim refusal and the explicit airborne longitudinal trim requirement.

Extend the synchronous bridge's `open_session(model_root, named_start, wind_profile="calm")` and facade's `start(model_root:String, named_start:String, wind_profile:Variant="calm")`. The bridge admits a real String Variant with one of the four IDs before creating the worker. Two-argument calls retain the original calm behavior through an explicitly registered default argument; prove both actual binding call forms. The facade performs the same type/ID admission before closing, replacing or allocating anything. Unknown starts/profiles and malformed arguments return rejected results without changing the prior facade, debt, held controls, sequences or recorder. Native wrong-thread/close/join rules remain.

Successful native open metadata adds exactly `wind_profile:String`, echoing the actually installed enum. The existing actual `AtmosphereSample/v1` supplies accepted numeric wind, session, tick, position, seed and atmosphere model. The facade verifies the echo, pinned native/model/world identities, seed42/runtime120Hz and the complete initial aircraft/weather pair before adoption. It checks actual initial wind against the selected table entry using the new predeclared component-agreement criterion below. Missing, incompatible or contradictory wind/metadata is an initialization failure; do not trust an echo in place of actual weather. Unknown extra wind setup fields are rejected. Pressure, temperature, density and `atmosphere_model` retain the same dry ISA implementation at the actual accepted position; wind changes neither their source nor their initialization policy. Comparisons use matching position/height, since a different accepted trim state can otherwise change ISA values without a weather-source change.

Keep the exact ADR007 Result and Readback keys and existing v1 wire schemas unchanged. The facade retains only a private accepted selection for its existing `reset(named_start)`; reset repeats that accepted selection and ignores any scene draft. An explicit new `start` without its third argument selects calm. `close` joins as before and can retain labeled historical copies; it does not create a weather-edit capability. A scene can track its accepted choice only after successful start, not from an unverified menu request.

### Requested and accepted physical state

At initialization, convert requested toward-NED SI components to the pinned JSBSim feet/s boundary by dividing each by the exact SI definition `0.3048`. Configure turbulence off and wind during IC preparation, before RunIC/trim, rather than injecting it into a completed aircraft state. The existing order is wind IC followed by body U/W setters; preserve and prove the requested body **ground-relative** velocities from ADR006 through actual `GetPropagate()->GetUVW()` immediately after RunIC. IC setters preserve related internal quantities and are not independently sufficient evidence of final ground-relative semantics. Wind changes air-relative motion; the ground recipe remains initially stationary with full brakes. Never subtract the wind from the requested ground velocity to keep TAS or the original calm trace unchanged.

Airborne preparation remains explicit longitudinal trim using the accepted solver settings and fuel freeze, with actual resulting aircraft state and solved controls visible at tick zero. Trim may alter requested velocity/attitude/controls; do not relabel those requested values as accepted state. A crosswind does not imply wings-level lateral trim, a crabbed course or automatic heading hold. Unsupported or failed trim rejects and joins the new worker; no retries with calm, weaker wind, changed coefficients or relaxed tolerance are allowed. No hidden completed ticks, clock reset, ground snap or new control assist is introduced.

Verify actual `GetWinds()->GetWindNED()` publication immediately after RunIC, after trim, and at aligned completed ticks. Use actual ground-relative motion and attitude to prove ADR009's `air_NED = R(body_to_NED) * ground_body - wind_toward_NED`, with turbulence zero, against independent expected cases and the backend air-relative result. Intermediate IC airspeed/angle getters and historical direction-function comments are not sufficient evidence of the final sign convention. If the existing component mapping fails that proof, hold implementation for a reviewed correction rather than changing the public vector semantics.

For this new leaf, predeclare **absolute nominal-wind disagreement at most `1e-6 m/s` per north/east/down component**, including requested zero components, immediately after actual RunIC, after trim when used, and at every admitted completed state. Compare actual native SI components to the unchanged table vectors. This engineering accuracy target is frozen before any new native output; it detects sign, axis and strength mismatches and is negligible relative to the intended `0.1 kt` speed and whole-degree true-bearing presentation. It is not a proved full IC/trim/libm error bound, a certified runtime accuracy claim or an expansion of any existing physics, trim or convergence budget. Direct SI/feet conversion proof remains separate from full IC reconstruction, repeated trim rotations and numerical-source uncertainty.

Publish actual accepted wind values unchanged. Do not clamp components to table values, classify tiny observed wind as calm, fall back to calm, retune the model or change existing solver tolerances to meet the target. Outside-target initialization rejects with an explicit error and joined worker; an outside-target prospective completed publication follows the existing terminal-fault/last-valid-historical policy rather than becoming an admitted current state. Retain actual rejected values and failure stage in bounded proof evidence. All six nonzero-profile/start combinations must meet the criterion and independent signed-airflow proof; criteria success alone does not establish physical aircraft fidelity.

## Scene choice and lifecycle

The ordinary scene owns a session-local draft selection and an accepted current selection. Default draft is calm on first launch. The chooser shows all four exact synthetic choices, speed and true wind-from direction, plus whether it applies to the **next fresh start**. Its draft labels cannot masquerade as current native conditions.

Changing a draft, opening/canceling its panel or selecting a runway sends no axes, lifecycle or native weather command. An explicit fresh ground/airborne start uses the draft through the existing start/discard gate. A normal Resume preserves current wind. Restart without a new selection repeats the accepted current wind; an explicit Apply-and-start action uses the draft. If recorded time has advanced, default-Cancel discard confirmation is required before replacement. File-operation, initialization and unresolved join gates block this action just as they block existing starts.

Invalid selections reject before replacing the current flight. Cancel preserves current aircraft/weather, native counts, debt, controls, mapper, origin, recorder and selected historical view. A valid accepted discard/start attempt may close the old worker; if new initialization fails, preserve its old **closed** recording prefix and current-choice history, report failure, and never report that the old flight remains live. Defer new recorder begin, current-choice adoption and draft-accepted labeling until initialization and ordinary scene setup succeed. No automatic resume follows failure, opening a panel or cancel.

The scene retains only its two bounded selection Strings. This is not a profile/preset store: no file, recent list, application-data directory, SQLite, auto-export or replay setup is introduced. These choices do not change or migrate input-preset v1/v2 formats.

## Native-truth wind presentation

Use a private pure view leaf `app/world/wind/wind_cue.gd`, loaded by preload, with static `from_readback(value:Variant)->Dictionary`. It is stateless and accepts an owned complete ADR007 Readback, qualified through unchanged ADR009 `NativeReadings.from_readback` and full aircraft/atmosphere validation. Its supported source domain is the exact original model/prepared world and reviewed native source closure implementing this contract's constant-local-NED field, seed42, dry ISA and zero turbulence. Caller admission requires the accepted scene/facade/native closure and its loaded-identity proof. The leaf checks the existing Readback's `model_identity`, `prepared_world_sha256`, `native_source_fingerprint` and available atmosphere/seed values; bind its supported fingerprint to the reviewed build without adding Readback keys. A fingerprint value cannot independently prove binary authority or the uniform field: those semantics come from source/build evidence. A merely well-shaped generic Readback, another source fingerprint or future spatial-weather implementation cannot authorize the fixed-anchor projection. Reject unsupported sources as invalid; a later source pin update needs reviewed evidence that this domain still holds. Future spatial weather requires a reviewed contract/context extension before this consumer can use it. The leaf calls no solver, facade mutator, mapper, camera or clock. Invalid, mismatched, missing or nonfinite weather never becomes calm. Ticks remain canonical uint64 Strings; do not convert absolute ticks into floats or signed integers.

Its exact owned `WindCue` value has these keys: `state:String` (`empty`, `live`, `paused`, `historical`, `invalid`), `session_id:String|null`, `tick:String|null`, `wind_toward_ned_mps:Array[float]|null` (exactly three binary64 scalars), `speed_mps:float|null`, `from_true_rad:float|null`, `wind_toward_airfield_eus_mps:Array[float]|null` (exactly three binary64 scalars), `error:String` (bounded to 1024). An invalid/empty cue has null identity/numeric values and a nonempty reason. Qualified cues copy session/tick and actual wind; error is empty. Only exactly zero horizontal wind has speed `0.0` and null direction. Finite tiny nonzero horizontal wind retains its actual speed/vector and derived bearing, rather than silently becoming calm. Returned arrays own their values; caller mutation cannot change a prior cue or Readback. State is the qualified ADR009 state; closed, stalled, coverage-blocked and discarded retained values are historical, not live or paused.

For horizontal toward wind `(N,E)`, speed is a robust binary64 `hypot(N,E)` equivalent: scale by the larger absolute component before squaring, so finite tiny nonzero components are not mistaken for zero through underflow. Bearing is null if and only if both horizontal components compare equal to zero, including signed zero. Otherwise wind-from true bearing is `atan2(-E,-N)`, wrapped to `[0,2pi)`; north is zero, increasing clockwise toward east. The nominal-wind engineering criterion applies to native preset acceptance, not observed calm classification, bearing availability or pure cue arithmetic comparisons. It includes vertical agreement to the requested zero component. Do not use a vendor direction getter or actual aircraft heading as the from-bearing formula.

The airfield direction follows this declared constant-local-NED field at the prepared anchor, so its fixed-anchor east/up/south vector is `(E,-D,-N)` from copied native components. This projection is appropriate to this specifically uniform NED preset; it is not an ownship-local-NED-to-ECEF conversion for a general spatial wind field. Render-origin translation changes no wind direction. No body yaw, camera yaw, smoothed pose or rebased ownship position enters it.

The existing windsock stays at its original fixed airfield position and adds no collider or native contact. A nonzero cue points its downstream end toward that wind; calm droops. Treat shape and extension as **STEADY PRESET / DIRECTION CUE**, with no calibrated extension-versus-speed or gust animation claim. Magnitude/from-bearing appear as **SYNTHETIC STEADY WIND / NATIVE TRUTH**, not measured wind, AWOS/ATIS or sensor information. The optional map arrow points toward flow and explicitly says TO; text says FROM with degrees true and units. Historical wind must say retained/historical, or hide the physical sock's current-looking indication. Invalid/empty wind suppresses numeric guidance/arrow and shows unavailable; it cannot display the last vector as current. Ordinary pause remains a labeled valid fixed-tick condition.

## Recorded-review compatibility

ADR011 Recording v1 and ADR012 archive v1 remain byte/shape/type/version compatible; do not edit their producers, scalar/text fixtures, metadata, tags or review restoration. Their metadata has no wind profile/vector, and their samples are captured readings/path/held axes, not the complete native weather record. Same seed/named start is not enough to reconstruct this added wind setup.

Display **Saved reviews do not retain wind setup or resume a flight** beside wind selection and current review/file guidance. Existing captured TAS/ground-speed/track may reflect nonzero wind, but neither a saved file nor its source fingerprint authenticates the chosen weather or supplies a restart recipe. Do not add a hidden weather/profile field, encode it into seed/session ID/named start, infer it from recorded TAS, silently reopen it as calm, or claim a complete briefing snapshot. A future recorded-weather setup needs a separate reviewed versioned contract.
