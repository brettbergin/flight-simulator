# ADR 020: Original audio cues and paused Audio controls

Status: proposed contract for [PROTOTYPE-AUDIO-CUE-CONTRACT #187](https://github.com/brettbergin/flight-simulator/issues/187). Normative only after its checked contract PR merges. [ORIGINAL-AUDIO-CUES #188](https://github.com/brettbergin/flight-simulator/issues/188) requires that acceptance and explicit bounded P2 dispatch. This proposal does not accept [FLIGHT-AUDIO #25](https://github.com/brettbergin/flight-simulator/issues/25) or aggregate phase gates.

## Scope

Improve the two original synthetic profiles with wind-relative airflow, original engine synthesis and independent gains. Captions are initially a read-only optional summary inside a paused Audio modal. Live captions, measured engine load/torque, installed warning audio, C172 acoustics, durable settings and device/pilot qualification remain outside this contract. Do not claim this child completes REAL-020, PRD-018/020, UX-013 or #25.

Simulation remains sole state authority. Audio never submits commands, starts/resumes a worker, queries devices/physics, changes a camera, hides an existing aid or rewrites source publications. No native/wire/schema/model/preset interface changes.

## One source and a closed internal cue view

`AudioCues.from_readback(source:Variant)->Dictionary` is pure, owns a deep input copy and returns an owned exact ten-key dictionary. It first applies accepted NativeReadings._validate to its owned source, then reuses NativeReadings.from_readback and, for piston only, EngineStatus.from_readback. Their source/units/calculation semantics remain unchanged. Calling the existing pure structural validator does not replace Scene binary/adoption authority. It does not prove loaded DLL identity: Scene must pass only its current facade-owned publication matching actual adopted session/profile and accepted build identity. A structurally valid arbitrary dictionary is not evidence of native origin. Lost host/adoption failure passes empty input immediately; no cached snapshot fallback.

| Key | Type and meaning |
|---|---|
| session_id | String from valid source; null when unavailable |
| tick | Canonical uint64 decimal String from valid source; null when unavailable |
| profile_id | Exact original-interactive-prototype or original-piston-prop-v1 String; null when unavailable |
| state | Exactly live, paused, historical or unavailable |
| engine_mode | Exactly legacy, running, rotating, stopped or unavailable |
| shaft_radps | Finite nonnegative float, piston only with valid shaft+Running classification; otherwise null |
| legacy_throttle | Finite float0..1 from validated held_axes.throttle, legacy only; otherwise null |
| tas_mps | Finite nonnegative float from valid NativeReadings.readings.tas, unit m/s; otherwise null |
| starved | Actual valid EngineStatus engine.starved bool for piston; otherwise null |
| error | String, at most1024 characters; empty iff every applicable cue channel is available |

Source invalid/empty maps to unavailable: all identity/numeric/bool fields null, engine_mode unavailable and nonempty reason. Valid paused sources stay paused, with their actual session/tick/values; pause is not historical or missing data. Actual terminal source with publication stays historical; no retained value is relabelled live. Error precedence: a failing full-source structural/semantic validation clears the whole view. With a valid nonempty full source, preserve session/tick/profile and derive live/paused/historical from its already-validated flags. If NativeReadings then reports derived-arithmetic overflow, set tas_mps null and report airflow unavailable; do not mute independently valid engine channels. Do not match against the null identity of that arithmetic-error readings result. When NativeReadings returns a qualified state, its state/session/tick must match the copied source; mismatch clears the whole view. For piston, EngineStatus state/session/tick must match that same structurally validated source; mismatch clears the whole view. A missing/invalid engine channel clears only engine interpretation, a missing starved channel clears only starved, and absent TAS clears only airflow. Never infer that any derived-arithmetic failure authorizes a malformed full source.

Engine classification: valid Running=true and shaft>0 => running; Running=false and shaft>0 => rotating; Running=false and shaft=0 => stopped. Missing/invalid Running/shaft or Running=true with shaft0 => engine_mode unavailable and shaft_radps null, with complete reason. This last case suppresses an unsupported sound interpretation, not a claim the backend state is impossible. No inference from throttle, mixture, ignition or starter request. Rotating deliberately does not distinguish cranking from coasting. Legacy mode uses validated native-held throttle and is labelled Synthetic throttle cue — not measured RPM. Missing TAS mutes airflow only; missing engine channels mute engine only; valid source state remains current/paused/historical. Missing starved stays null, not false; this field is panel information only and never causes a new alarm or mute an otherwise qualified engine/airflow cue. Join applicable component error messages deterministically (engine, airflow, starvation), truncate only diagnostic length with explicit suffix; do not shorten required visible source category. Unknown keys/types/states reject at every consumer boundary without accepting partial input or retaining old current cues.

## Options and presentation APIs

Options have exactly four keys: `enabled:bool`, `engine_gain:float`, `airflow_gain:float`, `show_panel_captions:bool`. Gains finite0..1; bool/int/coercion/NaN/Inf, missing/extra keys reject. Defaults true,1.0,1.0,true. Pure `AudioOptions.validate(value:Variant)->Dictionary` returns exactly `{ok:bool,error:String,value:Dictionary|null}`: success true/emptyerror/ownednormalizedcopy; failure false/nonemptyerror/null. Identical valid options are idempotent. Preferences last for this application instance across fresh flight/profile resets, never persisted.

Sound adds `observe(source:Variant)->void`, reducing and storing an owned cue view, and `set_options(value:Variant)->bool`, strict all-or-nothing admission. Existing `set_enabled(bool)` remains a compatibility adapter to the same enabled field; there is no competing second master state. Scene alone owns authoritative application options: the existing audio action updates options.enabled once and passes one validated options copy to sound/panel. A panel checkbox requests the same single Scene path; it cannot toggle independently then emit another toggle. Master mute never modifies source/caption qualification. Sound source cannot be changed by panel callbacks.

`AudioPanel.set_context(cues:Variant,options:Variant)->bool` validates both closed shapes before replacing owned context; rejected context preserves previous context and cannot become current. Root must explicitly replace/invalidate context on source lifecycle changes instead of relying on rejection to clear stale values. Signals are `options_requested(options:Dictionary,source_session:String)` and `dismissed`. Panel emits only an owned full options copy, with the session of its admitted paused context. On each opening, Scene captures the actual adopted paused session and actual panel instance in the connected callback. Each callback also captures an internal per-opening active guard, invalidated/disconnected on Back/close/adoption/failure; queued callbacks from a retired opening reject even if the same session later opens the same panel again. This is local callback lifetime bookkeeping, not a new token schema. Scene accepts only when that opening remains active, its actual panel is visible/current, the captured session still equals the adopted paused source and there is no pending transition, then validates options again. Inactive/stale requests preserve previous options and emit no native/input actions.

## Paused modal and accessibility boundary

Audio entry is available only from the existing already-paused main menu with current adopted host_mode paused, no other modal/discard/archive/adoption and no live capture. It never invokes pause to get permission. If engine pointer/look/starter capture is still pending/active, deny opening rather than fabricate a release. The ordinary explicit pause owner must retire real capture before entry; no second retirement or synthetic button-up. Paused native-held starter/axes remain exactly held. Resume continues to use existing real Raw neutral/release/rearm checks; opening/closing Audio never clears a latch to make Resume succeed.

Replace the existing single flight-speed menu row with a two-button row (expanding existing speed plus Audio), preserving menu height and existing six-button cockpit row. Actual minimum960 font/hit/focus fit is consumer acceptance, not proved here. New opaque full-viewport scrolling modal follows existing Wind panel's24px margins/wrapped labels/Back pattern; no flight overlay geometry changes. Contents: original-synthesis title/explanation, Master, two labelled gain sliders/percentages, Show source captions in this paused panel, source qualification/error, optional cue detail and Back — keep flight paused. No preview tone or hidden flight advancement. Required qualifier remains even when optional details hidden. Paused running text explicitly says PAUSED — no audio playing, and retains actual engineering running/shaft/TAS facts. Historical/empty source does not qualify entry; if source is lost while open, replace context with unavailable, disable option requests and return to paused/recovery menu via existing lifecycle. Never show prior live summary as current.

Root integrates audio page into all existing enumerated modal/input/pointer/visibility/reset/close/discard paths. Audio-specific joy/key handling must run before generic paused Resume branches; reject unrelated dispatch/open-other-modal requests while Audio is open. Escape or configured pause-menu action returns to main menu, remaining paused; does not Resume. Keyboard/controller focus is explicit and Back regains menu Audio focus. Existing master audio action admission elsewhere stays unchanged; this contract adds no new binding. No Help/HUD/map/circuit/engine expansion/camera flags are forced. Full controls/source errors scroll instead of clipping. **Paused summary is not live audio accessibility.** Live captions and captions for critical warning indications remain open under25/64, needing a separate reviewed live-placement policy.

## Sample timing and lifecycle

Scene delivers observe synchronously on accepted adoption, pause/resume, fault, failed adoption and close, including empty host publication; a later _process call or nonempty cached snapshot is not a lifecycle guarantee.

Existing separately runnable preview keeps `update_audio`, `update_engine_audio`, `set_enabled`, `close`, `shutdown` signatures and prior proof compatibility; ordinary Scene uses observe. Legacy preview scalar inputs are not silently reinterpreted as TAS, and its old proof must not be reported as new ordinary-source qualification. New production synthesis is a fixed-count sample renderer at22050Hz. Phase/RNG/envelopes advance only per rendered sample; draw delta does not determine phase. Same cue/options event schedule at identical sample offsets must produce identical samples for different buffer partitions. This excludes differing host arrival schedules, device buffering and hardware latency.

Original authored mix: legacy throttle pitch43+72*smoothedThrottleHz; piston running base2*shaft/TAU with1/.36/.12 harmonics and amplitude.17; rotating sine amplitude.04; stopped/unavailable engine0. Airflow noise uses accepted TAS with amplitude.13*clamp(TAS/90,0,1);90m/s is artistic scaling, not aircraft limit. Seed8017 and per-sample noise smoothing.07 retained; omit each harmonic at or above.45Fs. Independent gains0..1 and existing player volume-12dB retained. The .4408/.3816/.17 bounds are pre-output-volume digital sample bounds, not sound-pressure levels. Original20ms per-sample gain/source envelope alpha=1-exp(-1/(Fs*.020)); convex gain transitions must respect bounded component amplitude. Conservative peak bound legacy.4408, running.3816 and rotation.17, below.45. No torque/load inference, sampled recordings or new warnings. Exact renderer is tested, not a test-only mirrored formula.

Only state live with enabled=true can queue audio. Valid paused values remain available to the panel but cannot play. Enter pause/mute/terminal/invalid or change session: immediately stop/detach the current playback and discard its queued frames, retain a weak retirement reference, and hold output inactive until all retired playback references clear. No unsupported clear-buffer API is assumed. Reuse at most one AudioStreamPlayer; attach/start a fresh generator playback only after retirement and actual eligible source. A delayed retirement causes silence, never a native pause/step or silent pass. Existing async shutdown observes all retiring playback references and reports false if not retired within its declared existing budget; no weakened timeout assertion. Global source invalidation drops stale render state; partial unavailable engine or TAS zeroes only the affected component target. Same-session pause/mute preserves oscillator/RNG position with no silent sample advancement; fresh session resets phase/noise/envelope/seed/samplecursor. Resumption starts zero output envelope and new buffer from the newest admitted live source, not old queued samples. These are synthesized-sample rules, not a promise of no hardware clicks under all drivers.

## Acceptance for the implementation child

Actual production sample partition equivalence, coefficient/finite/nearNyquist tests; independent source TAS counterexamples that fail existing ground-norm behavior; closed-shape/type/unit/state/copy/session/profile negatives; partial channels and paused/historical captions; options atomic rejection/idempotence/master singleauthority. Actual stopped/cranking-or-coast-neutral/running distinctions must follow supported channels, no warnings from intents. Real current-source native/Raw/held/debt/mapper/origin invariance around options, and rejected pending-capture/starter/rearm cases; actual paused UI font/focus/hit/Back behavior at960. Repeated reset/mute/pause/close leaves one emitter, no stale queued sound and actual audio retirement observed. Affected package/source/notice and current CI remain delivery-owned. Report exact Windows listening/output scope only if exercised; sample math is not deviceQA. Unchanged aircraft numerical proof need not rerun. #25 remains open for load/warnings/live accessibility and later source/human/device gates.
