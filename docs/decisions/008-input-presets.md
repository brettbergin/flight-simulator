# ADR 008: Pilot input presets and paused calibration

Status: proposed contract; normative after its contract PR merges. Contract issue [#116](https://github.com/brettbergin/flight-simulator/issues/116); consumer [#21](https://github.com/brettbergin/flight-simulator/issues/21). Contract PR must merge before its consumers. P1/#20 dispatch acceptance and later device/human evaluation remain separate. Uses accepted [ADR004](004-persistence-and-replay.md), [ADR006](006-interactive-prototype.md), [ADR007](007-sim-loop-facade.md) and unchanged [ControlCommand/v1](../contracts.md) axes. No new wire fields, native driver, aircraft model or generic device framework.

## Decision

Add a small main-thread input mapper, preset codec and Controls panel. The existing flight scene remains the coordinator: it samples devices, sends a complete pilot intent to Facade.set_axes, and owns pause/restart/view actions. The mapper never receives aircraft attitude/velocity, calls native, sets ticks/authority, or supplies stabilization feedback. Persisted input presets are explicit interchange files, not a second automatic settings/profile authority.

An action row shows binding/source, raw bar, mapped bar and validation text. Edit/learn/calibrate/apply/restore-defaults/import/export operate only while the native facade is verifiably paused. A draft edit does not change the active mapper or native held axes. Apply validates the complete preset atomically; failure preserves the prior active preset. The panel distinguishes pending pilot intent from native-held values.

## App seam and ownership

InputMapper.configure(preset:Dictionary, held_axes:Dictionary, start_axes:Dictionary, initial_raw:Dictionary)->{ok:bool,error:String}: validate/deep-copy all four values atomically; initialize rate/held axes from actual held controls and fixed start bias from accepted start axes. Pin each referenced device slot to initial_raw connection generation and require every bound axis/button index to be present in its observed sparse readings. Missing/unobserved controls reject; neither saved GUID nor runtime numeric index substitutes for an observation. Successful configure enters nonflight/suspended mode. Configuration changes only while caller verifies native pause.

InputMapper.sample(raw:Dictionary,elapsed_us:int)->{ok:bool,error:String,axes:Dictionary|null,actions:Array[String],takeover:Array[String],brake_hold:bool}: pure copied source readings; returns one complete existing axes payload when safe. elapsed_us0..250000; invalid values reject without filter advance. Controller handles facade overload first; it must not hide a large gap by clamping input time. Results contain no clock/sequence/source/authority. actions are discrete press transitions, never OS key-repeat events. Continuous full-brake held buttons are applied to axes in the mapper, not emitted repeatedly as discrete actions. Input cadence is host sampling; exact replay equivalence concerns identical admitted commands, not separately polled keyboard traces.

InputMapper.suspend(reason:String,held_axes:Dictionary)->{ok:bool,error:String}: enter nonflight immediately, clear capture/edge state and validate/copy held axes to rearm takeover; invalid held values report failure while remaining nonflight and preserving the previous valid held/filter values. While suspended, sample(raw,0) updates diagnostics only: axes is the copied held payload, actions=[], input/filter state and pacing debt unchanged; nonzero elapsed rejects. InputMapper.resume_confirmed(current_raw:Dictionary)->{ok:bool,error:String}: revalidate pinned generations and sparse observed controls NOW, centered neutral within0.05 and every persistent key/button contributing to a flight axis or brake/idle override released; failure remains nonflight. The initiating menu/resume key or click does not block recovery; resume primes all discrete-action edges from current_raw so that held UI inputs cannot fire again in flight. Absolute throttle/trim takeover can remain unmatched after a successful resume and continue holding their copied held values until matched within0.03. Paused menu/view/cancel actions are handled by the panel/controller through the same validated preset bindings outside the flight sample; they cannot submit axes. Resume changes only mapper mode, not native pause; controller must separately obtain actual Facade resume acceptance. No implicit resume, neutral command or native submission.

InputPreset.decode(bytes:PackedByteArray)/encode(preset:Dictionary)->{ok,error,value:Dictionary|PackedByteArray|null}: bounded UTF-8 JSON, no executable objects/resources. InputPreset.save(path:String,preset:Dictionary)->{ok,error}: explicit user-selected interchange path only; no arbitrary paths from the imported preset.

Exact Raw keys: keys:Array[int] (unique selected physical keys currently pressed, max64),mouse_buttons:Array[int] (unique pressed supported buttons),devices:Array[DeviceSample] (max8). DeviceSample keys: slot:String,generation:int,axes:Array[AxisReading],buttons:Array[ButtonReading]. AxisReading has exactly index:int,value:float; ButtonReading has exactly index:int,pressed:bool. Both arrays have unique observed indices; absent controls are absent entries, never fabricated zero/false. Axis value must be finite[-1,1]. At the pinned Godot4.7.2 backend, indices/counts satisfy0<=axis<JOY_AXIS_MAX and0<=button<JOY_BUTTON_MAX (the engine enum bounds, not a gamepad-layout assumption); raw pressed physical/mouse codes use its supported Key/MouseButton enums. Device adapter tracks actual InputEventJoypadMotion/Button observations for this generation and polls only that observed set. Generation is a connection-local nonnegative counter; selection records the expected slot generation. Missing/duplicate/stale generation rejects axes before use and requests pause. On counter exhaustion require fresh mapper/device selection, never wrap. Raw arrays are copied; key codes/device indices cannot name methods or resources. Sample results always contain all six keys; failure axes=null/actions=[]/takeover=[] and explicit error, while brake_hold reports the unchanged mapper latch (false before first successful configuration). Successful takeover lists unmatched target names in stable order while axes hold prior pilot values for those targets.

The Godot device adapter polls only selected bindings and observed sparse raw axis/button indices. It emits the exact owned Raw device slots/generations with sparse index/value and index/pressed readings; there is no additional binding-ID field. The mutable InputEvent/device objects remain local to the main thread. This is one adapter to the pinned backend, not an extensible driver subsystem.

## Closed preset format

Top-level InputPreset/v1 keys: type:"InputPreset",version:1,name:String,devices:Array,axes:Array,actions:Array. No extra keys. name1..64 chars; devices<=8, axes exactly8 unique targets roll/pitch/yaw/throttle/mixture/left_brake/right_brake/trim; actions<=64 unique action IDs. File<=64KiB, nesting<=8; finite numbers only. Unknown versions/fields, duplicate targets/actions, invalid range/gain and unsupported backend indices reject intact.

Device entry: slot:String (unique ASCII identifier<=32),label:String<=64,match:Dictionary with guid/name/vendor_id/product_id Strings bounded128/128/16/16. Empty metadata is allowed when unavailable. Runtime device IDs, serials, session/tick/build/aircraft state, profile identities and file paths are forbidden. A saved selector is a hint; ambiguous identical devices require an explicit selection for this connection generation. Never automatically choose the first matching GUID or reuse a numeric device index after unplugging.

Axis entries use one closed discriminator:

- joy_axis: target,kind,slot,index,range (centered/unsigned),minimum,center,maximum,invert,deadzone,saturation,gain,slew_per_s. Finite numbers; raw[-1,1], each centered span>=.05; unsigned span>=.05. deadzone0..0.4, saturation strictly above deadzone and<=1, gain>0 and<=1, slew0..4 normalized units/s (0 means direct). index must be observed and within pinned backend bounds.
- key_pair: target,kind,negative:Array[int],positive:Array[int],rate,gain,return_to_start. Each physical-key alias array has1..4 unique valid codes; the two sets are disjoint. A side is pressed when ANY alias is pressed; multiple aliases do not multiply its effect and opposing sides cancel. rate>0..4, gain>0..1; return_to_start supported only on roll/pitch/yaw. An unsigned key pair holds its last pilot-selected position when released.
- fixed: target,kind,value. Value must satisfy that target's accepted command range and current prototype capability. This is a visible fallback binding, not hidden assistance.

Action entry has exactly id:String,sources:Array[Source] (1..4 unique aliases). Source is closed physical_keys{kind,keys:Array[int]} (1..4 unique valid codes), joy_button{kind,slot,index}, or mouse_button{kind,button}. Allowed IDs: pause_menu,restart,start_ground,start_airborne,idle,left_brake,right_brake,both_brakes,brake_hold,view_cycle,view_cockpit,view_chase,view_orbit,view_panel,map_toggle,runway_toggle,map_zoom_in,map_zoom_out,look_hold,view_zoom_in,view_zoom_out,recenter,help,overlay,controller_select,audio,fullscreen,speed_down,speed_up,controls_panel. No imported method names or extra actions. left_brake/right_brake/both_brakes/look_hold are held actions; the first three contribute to mapped axes, look_hold affects only camera capture. Other actions emit once on press, not OS repeat. Wheel-button presses are latched until one eligible live sample then released; multiple same-wheel presses before that sample coalesce explicitly. Paused UI consumes or discards its wheel pulses immediately; transient wheel indices4..7 never participate in the persistent button-release resume gate or leak into the next flight sample. Remapping conflicts are diagnosed across axes/actions and capture ignores echo/mouse motion/unknown devices. Reserved Escape remains available to cancel editing and pause. Learn requires release, then a deliberate selected-source input; neutral noise cannot capture an axis.

## Mapping and authority

Exactly one primary source owns each axis. Centered analog maps each side of calibrated center separately to[-1,1]; unsigned maps min/max to[0,1]. Apply inversion, deadzone/saturation remapping, explicit gain and optional wall-time slew, then clamp to command range. Brake pedals use unsigned rest/end calibration. Calibration records actual raw endpoints/neutral; it does not calibrate aircraft performance.

Preserve current keyboard preset and visibly show its solved-start bias and input shaping: arrows roll/pitch, A/D yaw, W/S and PageUp/PageDown throttle, brackets trim, Q/E differential brakes, X idle, Space full brakes and B hold; same view/menu controls and F5/F6 pacing. Legacy keyboard gains0.35/0.15/0.25 for roll/pitch/yaw and slew0.9/s remain an explicitly named smooth preset: target is clamp(start_axis + gain * digital_sign,-1,1), moving toward it by0.9*elapsed_s. Throttle key_pair aliases positive[W,PageUp],negative[S,PageDown] hold when released and integrate0.25*elapsed_s*sign; trim bracket pair integrates0.08*elapsed_s*sign. Aliases pressed together contribute once. Existing arrow and A/D pairs preserve their signs. Direct hardware preset uses full linear throw by default; deadzones/gain/slew are editable, with raw/mapped bars. Keep mouse look/view gestures outside flight axes in this first slice.

The mapper owns the runtime brake-hold latch. Its first successful configure seeds it from accepted start_axes.left_brake>0.5 AND start_axes.right_brake>0.5; a fresh mapper is created for every fresh native session. The brake_hold action toggles it once on a rising edge. Later successful preset reconfiguration, suspension, pause/focus loss and resume preserve it; do not infer a persistent latch from momentary held Space/Q/E or pedal values. The copied sample.brake_hold value supplies visible ON/OFF status, including paused diagnostic samples. This latch is never serialized in a preset.

Only declared left/right/both-full-brake and brake-hold actions may override the primary brake axes, visibly; this preserves Q/E/Space/B. Default keyboard brakes have primary fixed0 and those explicit held-button overrides. Releasing returns to actual mapped pedals/buttons. X idle sets pilot throttle intent0 and rearms throttle takeover so an unmoved hardware lever cannot immediately restore power. No last-moved-device mixing or automatic rudder/yaw stabilization.

Runtime presets MUST contain mixture as fixed with value1; any other mixture binding/value rejects configuration/import as incompatible with ADR006. Pure unsigned mapping-kernel tests can exercise0..1 independently without representing a runtime mixture capability. The Controls panel explicitly disables mixture for this prototype and output fixes1; no apparent movable lever or silently rejected in-flight mixture command. Flaps/gear/system controls remain unavailable. #21's full independent-mixture/hardware criterion remains open until its supporting model and actual hardware qualification exist.

## Removal, takeover and focus

Removal of ANY active flight source, focus loss or invalid raw sample pauses through Facade.set_paused(true) before another solver advance. Failed pause is visible and blocks further advancement; close/join/reset recovery follows facade semantics. Do not submit guessed neutral or stale maximum controls. Pause itself preserves actual held axes.

On reselect/import/profile apply/reconnect, centered controls must be within0.05 of calibrated neutral, buttons released, and throttle/trim absolute controls need explicit soft takeover within0.03 normalized units of held state. Until matching, retain that axis's held value with a visible mismatch/takeover bar. Digital rate controls initialize from held values; suspended diagnostic samples do not integrate them or produce view/flight actions. Matching devices/reconnection never resumes; the user explicitly confirms recovery. Fresh sessions reset connection/capture/filter/edge history. No calibration writes during flight.

## Storage, privacy and bounded writes

Preserve ADR004: SQLite remains authority for future pilot profiles/settings/progress in the native Known Folder-resolved root. First-slice Save/Load/export/import writes only the path explicitly selected by the user; no automatic user:// controls settings, launch autoload or profile-name inference. Defaults initialize each launch until explicit Load. An unsaved/guest active preset is transient and labeled. #34 later imports explicitly selected presets into its profile settings through its own migration authority.

Write same-directory temporary file, flush/close, reread/decode and verify bytes, then replace using a tested atomic operation; report Save success only after replacement. A failed/unsupported import or failed write preserves the current active preset and original file; retain temporary diagnostic files on failure without deleting a user target. Test replacement support on Windows before claiming atomicity; unsupported filesystems get a clear unsaved result. Exports omit device serials/runtime indices; no telemetry/upload. No flight logs or pilot data are included.

## Acceptance and implementation slice

Contract owns this app/preset seam first. Consumer owns app/input/{input_mapper,input_preset}.gd, app/ui/controls/controls_panel.gd and tests/input/, with root-coordinated flight_scene adoption/menu button/paused recovery. Avoid editing native, original model, schemas or SQLite.

Active offline mapper tests cover asymmetric ranges, reversal, noise/deadzone/saturation, independent pedals, invalid spans/NaN/unknown versions/oversize/copies, source ambiguity, axis-index reuse, calibration capture and release/soft takeover. A ground start with accepted0.8/0.8 brakes seeds full hold until B toggles it; pause/focus/menu/profile Apply cannot release it, while an airborne start has latch false. Synthetic removal/focus tests use the actual facade and prove pause before next native tick; input shaping tests compare explicit timed sampling fixtures at30/60/144Hz, not arbitrary human input traces. Preset tests prove truncated/corrupt imports and interrupted writes/replace failures preserve old data. Actual exported Windows UI evidence covers960x540 and1280x720: open Controls while paused, capture/remap a key, inspect raw/mapped axis bars, calibrate or reject an incompatible range, Apply/Cancel, export/import preset, disconnect/reselect and explicit takeover. Default keyboard/gamepad walkthrough plus available yoke/pedal checklist identifies hardware truly tested; #65 remains broader hardware QA. Manual flight completion and P2 gates stay open without their actual evidence.
