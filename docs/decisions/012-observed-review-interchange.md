# ADR 012: Explicit recorded-review interchange

Date: 2026-10-04. Status: proposed; no consumers until a reviewed contract PR and coordinator dispatch. Contract issue [#136](https://github.com/brettbergin/flight-simulator/issues/136). Partial support for PRD-025, UX-017, UX-018, UX-021 and UX-022; this does not complete those requirements. Basis: [ADR011](011-observed-flight-review.md), accepted contract PR [#133](https://github.com/brettbergin/flight-simulator/pull/133), and its separately reviewed implementation [#135](https://github.com/brettbergin/flight-simulator/pull/135), whose merge and delivery evidence must precede consumers. This proposal changes no recorder, public simulation schema or native authority.

## Outcome and scope

The player can explicitly **Save new review** to a chosen local file, then **Open recorded review** in a separate paused historical view. V1 creates new files only. An existing file, directory or reparse target is a refusal: choose another name. There is no overwrite confirmation or replacement operation in this leaf.

A saved file contains one immutable copy of a qualified ADR011 Recording: at most 2,401 actual samples on the existing 20-minute window. It preserves actual ticks, skipped targets, lateness, missing channels, the observed endpoint and seal diagnostics. Saving a record whose state is `recording` captures its present prefix; it neither seals nor clears the current recorder. Labels remain **RECORDED OBSERVATIONS / ORIGINAL PROTOTYPE**, with **OPENED FILE / HISTORICAL** on imported views. A checksum is corruption detection, not proof of authenticity, calibration, pilot actions or training credit.

This is an explicit selected-path guest interchange exception, consistent with [ADR008](008-input-presets.md). [ADR004](004-persistence-and-replay.md) retains authority for future automatic application data. Introduce no Known Folder lookup, `user://` store, SQLite writer, profile, index, automatic library, autosave, recent-file history, background upload or new native persistence service. Broad issues #34, #74, #75 and #35 remain open. No complete command/event history, SessionManifest, ReplayHeader, checkpoint, physics seek or combined ground-flight resume is claimed. The current memory record still disappears on unplanned process termination unless the player has explicitly saved it.

## Closed archive and integrity

Use a plain, uncompressed UTF8 JSON file, conventionally named `flight-review-<friendly suffix>.fsreview.json`. The extension is a chooser aid, not validation. No BOM, resource loading, executable objects, scripts, links, attachments, compression or external references are accepted.

The outer object has exactly these five literal keys:

| Field | Required value |
|---|---|
| `format` | String `ObservedFlightReview` |
| `archive_version` | Canonical JSON integer token `1` |
| `recording_contract_version` | Canonical JSON integer token `1` |
| `payload_json` | String containing the exact inner JSON text defined below |
| `payload_sha256` | String of 64 lowercase hexadecimal digits |

`payload_sha256` is SHA256 of `payload_json.to_utf8_buffer()` after strictly decoding the outer JSON string, without a BOM, newline insertion, Unicode normalization or reserialization. The digest covers the entire inner text, including every recording identity, sample, diagnostic and numeric tag. No JSON canonicalizer or self-referential whole-file hash is needed. Outer key order and insignificant whitespace do not affect this binding; inner whitespace changes its digest. Unknown versions reject intact; there is no migration or best-effort conversion. Format/version fields are exact constants admitted before the payload, not independently trusted caller metadata.

The inner root is precisely the closed ADR011 Recording tree with the numeric representation below. It contains no additional archive metadata, save timestamps, username, host path or synthesized provenance. Empty recordings cannot be saved or opened: archive admission requires a valid nonempty `recording` or `sealed` Recording. A valid failure-sealed prefix is allowed and its reason/error remain visible. Import accepts only the existing ADR011 original-interactive model, prepared-world identity, seed and runtime clock; an older valid source fingerprint may remain descriptive. Import does not require or load its old executable, model or library. Reuse the accepted closed validator rather than weakening it to accommodate other airplanes or worlds.

## Exact numeric representation

Every in-process `TYPE_FLOAT` leaf is replaced by an exact one-key object `{"$binary64_le":"<16 lowercase hexadecimal digits>"}` at a schema-recognized numeric position. Its value is the eight IEEE 754 binary64 bytes, least-significant byte first, hex-encoded in byte order. For example, +0 is `0000000000000000`, -0 is `0000000000000080`, and 1.0 is `000000000000f03f`. This is this archive's defined format, not a generic Godot Variant serialization format. Preserve all finite bits, including signed zero and subnormal values; reject NaN and either infinity before encoding and after decoding. Decode exactly eight validated bytes and check finiteness; never treat an API failure/default 0.0 as successful admission.

The pinned [Godot 4.7.2 PackedByteArray binding](https://github.com/godotengine/godot/blob/4.7.2-stable/core/variant/variant_call.cpp) calls the scalar double marshaler. Its [marshaler source](https://github.com/godotengine/godot/blob/4.7.2-stable/core/io/marshalls.h) writes and reads uint64 bytes least-significant first. The [public API documentation](https://docs.godotengine.org/en/stable/classes/class_packedbytearray.html) describes 64-bit encode/decode operations but cautions against relying on unspecified external encodings. Therefore the leaf owns this explicit LE format and independently proves the pinned implementation against it; an engine update must repeat that gate.

Recognized numeric positions are exhaustive:

| Inner path, relative to Recording | Archive representation and restoration |
|---|---|
| `contract_version` | JSON integer `1` -> `TYPE_INT` |
| `skipped_target_count`, `late_sample_count`, `uncaptured_tail_targets` | Canonical JSON integer 0..2400 -> `TYPE_INT` |
| `metadata.world_anchor.{latitude_rad,longitude_rad,ellipsoid_height_m}` | Binary64 tag -> `TYPE_FLOAT` |
| `metadata.clock.tick_rate_hz` | Integer token `120` -> `TYPE_INT`, or binary64 tag for a supplied `TYPE_FLOAT` 120.0 -> `TYPE_FLOAT` |
| `samples[i].{late_by_ticks,skipped_targets_before}` | Canonical JSON integer within ADR011 bounds -> `TYPE_INT` |
| `samples[i].elapsed_s`, each `samples[i].anchor_eus_position_m[j]` | Binary64 tag -> `TYPE_FLOAT` |
| `samples[i].readings.readings.<channel>.value` | Binary64 tag -> `TYPE_FLOAT`, or null only for an invalid channel under ADR011 |
| `samples[i].held_axes.{roll,pitch,yaw,throttle,mixture,left_brake,right_brake,trim}` | Preserve supplied type: canonical integer token for `TYPE_INT`, binary64 tag for `TYPE_FLOAT`; then enforce the existing axes ranges and mixture=1 |

The channel names are exactly `tas`, `ground_speed`, `pitch`, `bank`, `heading_true`, `ellipsoid_height`, `vertical_speed`, `body_yaw_rate` and `fuel_total`; units and validity/error semantics are unchanged. All other leaves retain their existing exact String/bool/null types. In particular, session IDs, ticks, targets, first/last ticks and seed remain canonical String identities; no numeric restoration is attempted on them. Numeric tags at any other position, an unknown tag, multiple-key tag, raw JSON fractional number at a float position, StringName, Object or Resource reject. No `JSON.from_native`, `JSON.to_native`, `bytes_to_var`, `decode_var` or arbitrary recursive tag dispatch is used.

Only canonical bounded integer tokens are permitted anywhere in the JSON texts: `0` or an optional minus followed by a nonzero decimal digit and decimal digits, magnitude at most 2401, with no negative zero, leading zero, plus, fraction or exponent. Known integer fields are restored from Godot's parsed number to `TYPE_INT` only after lexical admission and path-specific bounds; arbitrary numeric fields never become ints. This also preserves integer-versus-float choices at clock/axes union positions. All restored Recording values must pass the unmodified ADR011 `Values.valid_recording`, then copy into a fresh `ObservedReview` candidate. Full-range uint64 ordering and relative metrics continue through the existing bounded string helpers, never absolute-tick float conversion.

The [Godot JSON documentation](https://docs.godotengine.org/en/stable/classes/class_json.html) describes a deliberately permissive parser. The [pinned JSON source](https://github.com/godotengine/godot/blob/4.7.2-stable/core/io/json.cpp) parses numeric tokens as double and serializes either signed zero as 0.0; `full_precision=true` alone does not preserve the required type/bit contract. Numeric tags avoid that ambiguity. JSON remains only a syntax container after independent strict lexical checks.

## Bounded strict decoding

Apply every bound to input before the corresponding allocation or traversal; encoding obeys the same bounds and fails before any filesystem operation. The whole file and decoded payload UTF8 bytes are independently at most 8,388,608 bytes (8 MiB). A full valid 2,401-sample record must be measured to fit both; do not truncate, discard diagnostic strings, round numbers or expand the cap to make it fit. An unusually large otherwise valid recording may be refused with an explicit size error. These byte/node caps are proposed admission budgets, not measured density results: independently count and encode the frozen dense 2,401-sample fixture before consumer acceptance, and report both actual value counts and byte sizes. A fixture that exceeds either cap requires a reviewed contract decision before consumers; never silently widen it.

Both texts require a bounded strict RFC 8259 scanner before `JSON.parse`, not only the existing InputPreset structural scanner. Reject duplicate keys in every object; escaped object keys are wholly forbidden, so `"\u0073tate"` cannot alias `"state"`. Object names must be the literal ASCII names of the closed archive/Recording/tag schemas, at most 64 bytes. Reject trailing commas, comments, trailing non-whitespace, non-JSON whitespace, bad literals, unescaped control characters, invalid escapes, lone surrogates, malformed numbers and misplaced separators. Escaped Unicode value strings may contain valid paired surrogates; they decode to scalar values without normalization.

Validate raw UTF8 before conversion: reject overlong encodings, incomplete sequences, surrogate code points, values above U+10FFFF, stray continuation bytes, BOM and NUL. Apply the same scalar-string checks to the decoded payload before its UTF8 conversion, so neither parser replacement characters nor cleanup can make malformed bytes acceptable. Genuine U+FFFD supplied as valid UTF8 is a character, not evidence of a decode error.

For each text, container depth is at most 16 (root object has depth 1); count at most 250,000 JSON values, including each object/array container and scalar. Arrays have at most 2,401 entries, with narrower schema bounds such as exactly three coordinate values enforced before numeric conversion. Objects have at most 16 members and exact schema keys. Ordinary decoded String values are at most 1,024 Unicode scalar characters and 4,096 UTF8 bytes, with all narrower ADR011 identity/enumeration/tag limits retained. The sole large-string exception is the outer `payload_json`, bounded by its decoded 8 MiB byte cap and the outer file cap. Its literal escape processing must remain bounded by the outer bytes. Keep work linear in admitted bytes/nodes; never loop through absolute ticks or execute attacker-provided code. Error messages are fixed/bounded to 1,024 characters and do not echo the whole file or local path into telemetry.

A checksum match does not bypass syntax, shape, type, model, sampling, tail, identity or finite-value qualification. A malicious author can compute a new checksum, so mark all opened files as imported historical observations rather than verified native flights. A failed decode exposes no partial recording.

## Paused ownership and historical display

The scene alone establishes a verified ordinary pause or confirmed joined stopped state. A pending pause, active native worker, failed join, unresolved reset or initialization cannot authorize Save/Open. The initial explicit pause may produce its ordinary observation; after the verified boundary, capture one deep owned `recorder.recording()` only on the explicit Save request. Preserve the original state, metadata, last observed tick, samples, errors and seal reason exactly in that snapshot. The scene freezes the session identity/action while a chooser or file operation is pending; it cannot reset, close for a new session or resume through that operation. Cancel leaves the already paused/stopped boundary unchanged and never implicitly resumes.

Codec and file leaves receive owned values/path arguments, no facade, recorder, mapper, camera, worker or scene references. They cannot call physics, update observed samples, set assists, clear a recorder, modify Readback or adopt an origin. A successful save changes only the new file and operation receipt. The current in-memory Recording remains active/unchanged and may observe further flight after an explicit later resume.

Open reads and validates a complete candidate before changing displayed historical state. Construct a fresh `ObservedReview` and call its existing `set_recording` only with the restored qualified record; that call's failure must not clear the already displayed review. Retain at most the one current ADR011 record plus one imported historical record. Successful Open replaces only the imported candidate/view, never calls `recorder.begin` and never adopts imported session IDs as current native state. Imported metadata must be displayed, including nonzero first tick, distinct last sampled/observed ticks, gaps and failure seals. Dismissing imported review discards that imported copy and returns to the paused current context without resuming. Error/Cancel preserves both current recorder and prior selected historical display/cursor exactly.

Imported views use the existing sampled channels/path summaries with explicit historical labels; no interpolation, route progression, scoring or native camera/ownship mutation follows a scrub. Save new review exports the current in-memory recorder only in v1, not the imported view. Any deliberate restart/quit still uses ADR011's discard confirmation even if a file was successfully saved; a successful write is not implicit permission to discard.

## Selected-path file operations

The default chooser proposes a friendly unique new name; collision requires another user-selected name. Both Save and Open accept only explicit absolute local Windows drive paths on NTFS with an existing ordinary parent directory, no `res://`, `user://`, UNC/network path, device namespace, alternate data stream or reparse-point target/parent chain. Paths are bounded to 4,096 characters; unsupported platform/path/filesystem capabilities fail before creating files. The Windows path/IO adapter resolves and rechecks these constraints and collision state immediately before installation. Existing targets of any kind are rejected for Save, including a file created after the chooser or while the temporary is written. Never remove or change a colliding target. The exclusive no-replace install protects against a target creation collision; path/reparse checks establish observed guard conditions, not atomic filesystem security against an external actor renaming parents or swapping junctions between checks and IO. V1 assumes the selected parent chain stays stable during the operation. Fail on observed guard/identity changes and test ordinary guard refusals plus target-creation races, but do not label check-then-move as adversarial path-race protection. Strong handle-based parent identity/reparse containment remains a separate filesystem-security design if that threat is brought into scope.

This adapter is local to the archive leaf. A reviewed fixed Windows PowerShell/.NET helper, similar in delivery to the accepted preset helper, may implement the platform calls; do not modify the global preset helper or its contract. Select the trusted SystemRoot helper path, pass user paths only as data with correct encoding, prohibit arbitrary command/script execution from archive values, and include the fixed helper in exact package/source audits. Missing helper/policy denial is a visible unsupported operation, with current flight preserved. No downloads, elevation, shell-policy changes or new runtime dependency are implied.

Save new follows these ordered boundaries:

1. Fully qualify and encode the immutable nonempty snapshot, then self-decode and compare its exact numeric types/float bytes/strings and structure. No filesystem writes on encode failure.
2. Qualify the chosen target and parent. Create a fresh same-directory temporary with exclusive create semantics and a unique leaf-owned name; never truncate a preexisting temporary or target. Write all bytes, check write/close/flush outcomes, request a reviewed OS-level flush, and read back exact bytes/digest plus full decode before installation.
3. Recheck no target exists and same local NTFS directory/guarded paths. Atomically move that verified temporary to the new target with no replacement permission. Use reviewed same-volume `System.IO.File.Move(source,target)` semantics; no overwrite flag, ReplaceFile, delete-then-rename, copy/delete or cross-volume fallback.
4. Read the committed target boundedly, verify its exact encoded bytes, hash and full Recording round trip again. Report success only then. No native state or current/imported Recording changes accompany success.

The [pinned Godot Windows rename](https://github.com/godotengine/godot/blob/4.7.2-stable/drivers/windows/dir_access_windows.cpp) removes an existing destination before moving, so it is unsuitable for this no-overwrite install. Its [file flush](https://github.com/godotengine/godot/blob/4.7.2-stable/drivers/windows/file_access_windows.cpp) calls C stdio `fflush`, insufficient by itself for the specified OS flush boundary. The adapter must prove its stronger flush call, such as [FileStream.Flush(true)](https://learn.microsoft.com/en-us/dotnet/api/system.io.filestream.flush?view=netframework-4.8.1), and actual [File.Move](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.move?view=netframework-4.8.1) no-overwrite behavior on the supported host. Same-directory atomic visibility and verified return are the scope; do not claim hardware power-loss survival or a transaction across filesystem and native state.

On pre-install failure, preserve the available temporary and every existing/racing target; report **Review not saved** and the local temporary path when present. After an unexpected move or post-install verification error, retain any target and available temporary without deleting or silently retrying, report **Save not verified; recovery required**, and expose only qualified local recovery paths. The target may exist even though success was not verified. A successfully installed temporary no longer exists under its old name; do not invent that recovery path. Do not clean unknown targets, scan a library or automatically recover at launch. The player can choose another name explicitly after failure. Opening a malformed/locked/missing file creates nothing. Unexpected process termination may leave a temporary or a committed file whose success was not shown; this is not an autosave/recovery guarantee.

## Proposed callable seam and receipts

Use new isolated leaves `app/replay/observed_archive/codec.gd` and `files.gd` (private fixed Windows helper if required). Do not edit ADR011 producer files. Stateless codec methods receive owned inputs:

| Method/result | Exact surface |
|---|---|
| `ObservedReviewArchive.encode(recording:Variant)` | CodecResult with `value:PackedByteArray|null` |
| `ObservedReviewArchive.decode(bytes:Variant)` | CodecResult with `value:Recording|null` |
| CodecResult | Exact `{ok:bool,error:String,value:Variant,payload_sha256:String|null}`; failure has null value/hash, success empty error and fully owned value/hash |
| `ObservedReviewFiles.save_new(path:Variant,bytes:Variant)` | FileResult, `value` always null; bytes must pass full decode before any write |
| `ObservedReviewFiles.open(path:Variant)` | FileResult with fully owned Recording on success |
| FileResult | Exact `{ok:bool,error:String,state:String,path:String,temp_path:String|null,value:Recording|null,payload_sha256:String|null}` |

FileResult state is `saved`, `opened`, `rejected`, `not_saved` or `recovery_required`. Success has the matching saved/opened state, empty error, null temp_path and a valid payload hash; saved has null value, opened has qualified value. All failures have null value/hash and explicit bounded error; rejected has no created temp_path. not_saved/recovery_required includes the available owned temporary only when established. path is the qualified chosen target when established, otherwise empty; local paths are displayed locally and never logged/uploaded by default. A filename or receipt is not proof the file committed. File operations belong to the file leaf's construction thread; foreign-thread calls reject before reading paths/files or mutating owner state with a canonical rejected receipt and empty path. Private IO helpers may work on copied bytes, but the scene must join/finish them before releasing its operation gate; no late callback can alter a restarted session.

## Independent gates before consumer acceptance

Freeze independent Python `struct` IEEE-bit references and exact archive text/digest fixtures before codec output. Include signed zeros, ordinary/fractional values, adjacent binary64 values, smallest/largest subnormals and finite normal extremes; bit-level codec tests are separate from whole Recording qualification, whose field ranges may reject some scalar fixtures. Verify integer-versus-float branches, null unavailable channels and full uint64 tick strings (including 2^53 boundaries and maximum). Test negative tags/unknown keys/wrong positions/types, infinite/NaN bits, integer grammar, strict UTF8/surrogate/escaped-key/duplicate-key rejection at both layers, checksum corruption and recomputed-hash invalid records, maximum bytes/depth/nodes/strings/samples, truncated files and future-version refusal. Never relax frozen expectations after observing output.

Before claiming durability, independently exercise actual Windows local NTFS exclusive temporary creation, complete write/OS flush/readback, Unicode/space paths, new-file atomic move, unchanged existing targets, competing target creation, temporary collisions, directory/reparse/network refusals, permissions/share locks, write/flush/move/post-verify failure injection and receipts retaining available recovery bytes. No Delete/Replace fallback may make a failing test pass. Test full dense 2,401-sample archive size and all float bits/types after encode/decode/Open. No mocked IO-only suite substitutes for the actual local NTFS proof.

Actual native/scene tests must compare current recorder, Readback/axes/debt, command/lifecycle counts, mapper, origin and joined ownership before/after Save/Open/Cancel/failure; distinguish the normal initial pause observation from forbidden file-operation changes. Test pending boundary refusal, active-prefix and rejection-sealed saves, no successful-save seal, older imported session/source metadata, paused scrubbing, previous review/cursor preservation, failed new initialization, imported dismiss and ordinary ADR011 discard guards. Exported and replacement packages require exact new leaf/helper/test source and UID/resource binding, mandatory nonempty test receipts, and visible save/open/collision/error/historical views at supported sizes. Pure codec/IO proof can be cross-platform where meaningful; install semantics and player interaction require Windows evidence. Native/engine/model/cache rebuilds are unnecessary for these source leaves unless their own independent changes require them.

Consumers wait for this contract, immutable independent references and an assigned implementation issue. Root owns scene/UI integration; a leaf owner owns codec/selected-path IO; an independent owner owns tests under `tests/debrief/observed_archive/`; delivery owns exact staging/package/CI audits. This contract closes no phase, C172, durable-profile, library, replay or training gate.
