## One canonical mosaic and source sampling

PixelIsArea georeferencing means sample centers, not upper-left corners. Define a single global1m sample lattice `(E,N)=(i+0.5,j+0.5)` for integer i,j. Tile row index is `5340005-j`; column is `i-549994` for55 or `i-559994` for56. Never apply an extra half-pixel shift or confuse increasing source northing with increasing image row/south.

At each lattice sample choose tile55 for `i<560000`, tile56 for `i>=560000`. This is fixed nominal-tile seam ownership inside the12-column overlap; even where both raw values exist, use only that owner. Do not average, choose the closer value, prioritize whichever is valid, search for a lower slope or emit overlapping independent surfaces. A missing owner's sample stays missing even if the other overlap copy happens to be valid. The receipt records the policy and the observed raw overlap discrepancy, not a claim of exact source agreement.

For a binary64 source query easting E/northing N, choose `i=floor(E-0.5)`, `j=floor(N-0.5)`, `t=E-(i+0.5)`, `u=N-(j+0.5)`. Require t/u in[0,1); no epsilon snapping. Fetch the four globally owned source samples H00(i,j), H10(i+1,j), H01(i,j+1), H11(i+1,j+1), each promoted exactly from f32 to binary64. All four must exist/qualify even if a weight is zero. Bilinear interpolation is precisely `a=H00+t*(H10-H00); b=H01+t*(H11-H01); H=a+u*(b-a)` in that sequence, separately rounded binary64 operations, no FMA/reassociation.
