# Offline terrain authoring tools v1

Status: proposed contract. Consumers require this contract and its [lock](../../../tools/ingest/terrain/tools-v1.lock.json) to merge with required checks before implementation. This pins a small offline authoring environment; it does not define a terrain codec, compiler, provider, contact surface, coordinate ABI, or geographic accuracy tier.

The initial supported host is Windows x64, Root's already frozen CPython 3.12.14 with the ordinary CPython 3.12 ABI. Its actual executable is 107312 bytes, SHA256 `d41bad46673f64e0d02f23797f53f90ccf60f27d6eda8d86dd2d4bbeae5a858c`; its observed build string is `3.12.14 (main, Aug 25 2026, 14:01:42) [MSC v.1944 64 bit (AMD64)]`. This supersedes the historical bootstrap 3.12.5 baseline for this tool only. Other interpreters, architectures and operating systems need a reviewed lock revision. Supply that existing interpreter explicitly and retain actual version, architecture, absolute path and hashes in the local qualification receipt. PATH does not select it implicitly.

The interpreter was frozen from an existing installed tool runtime with a complete retained file manifest, not acquired from a newly identified upstream installer URL. Its manifest SHA256 and core DLL/license hashes are locked. No original acquisition archive URL/hash has been established here; this first lock supports the retained local runtime only and is not a fresh-machine Python bootstrap promise. Check retained source/library files against the manifest, preserving the separately recorded bytecode-repair history; reject unexplained drift. The isolated terrain environment excludes inherited third-party site packages and writes no bytecode to the frozen base. A portable interpreter acquisition recipe is deferred rather than invented.

## Controlled files and offline behavior

The lock uses paths relative to a caller-selected absolute `tool_root`; it never embeds a user's profile path. The isolated environment is `tool_root/environment`, and the sealed data directory is `tool_root/proj-data`. Populate that data directory from the selected pyproj wheel's complete embedded PROJ data tree, retaining original files and notices, plus the one separately locked GEOID18 grid and its retained README. Produce a manifest of every installed data-file relative path/hash, verify it before each authoring run, and reject extra files. Do not alter proj.db or append alternate data directories.

Before importing pyproj, set `PROJ_NETWORK=OFF` and `PROJ_ONLY_BEST_DEFAULT=YES`; clear inherited PROJ_LIB/PROJ_DATA overrides and auxiliary database configuration. Set the process's PROJ_DATA to the exact sealed absolute directory. After import, set pyproj's data directory explicitly to that same single directory, call `pyproj.network.set_network_enabled(False)`, and verify the effective data directory and network-disabled state. Resolve and verify the loaded native library belongs to the selected environment. These are process-local settings, not global machine changes.

Use a dedicated empty working directory and set `PROJ_USER_WRITABLE_DIRECTORY` to an isolated empty absolute directory for each run before import. Do not read grids or databases from user profiles, current-directory leftovers, preexisting network caches or system GIS installations. Verify resolved grid paths are inside the sealed directory and match the lock before operation use; a filename-only availability check is insufficient. Qualification must establish the actual pinned pyproj/PROJ search behavior; if an uncontrolled fallback cannot be excluded, fail rather than proceed. No grid sync/download API or online fallback is permitted during an offline authoring run.

## Operation admission and receipts

The [versioned pyproj Transformer documentation](https://pyproj4.github.io/pyproj/3.7.2/api/transformer.html) distinguishes `allow_ballpark=False` from `only_best=True`: the former excludes ballpark candidates; the latter errors when the best known operation needs unavailable resources. `PROJ_ONLY_BEST_DEFAULT` is only a default, and explicit kwargs take precedence. Neither setting fixes a particular operation or proves source accuracy. An explicit `from_pipeline` operation bypasses candidate selection, so validate that operation's identity and resources directly.

For any future CRS-based selection, pass explicit source/target CRS, area of interest, authority policy, `allow_ballpark=False`, `only_best=True` and an explicit axis convention. Never choose the first available lower-accuracy candidate after a missing-grid error. Admit only the separately reviewed operation/ordered concatenation for the source package. For explicitly chosen operations, use an unambiguous authority/code or frozen definition; prohibit heuristic operation-name lookup, optional grids (`@`), null fallback grids and unreviewed concatenated steps.

Before processing source samples, retain source/target CRS definitions and dimensionality; full operation definition/PROJJSON; authority IDs, ordered steps, direction/inverse flag; axis order and input/output units; expected accuracy with unknown preserved; area of use and declared source coverage; grid names, full resolved paths, hashes and availability; and the selected data-directory/database identities. Check the complete source footprint and required inverse against supported coverage, not just one airport point. A grid registry bounding rectangle is not proof that every point has a valid correction. Transform with error checking and reject nonfinite/out-of-domain results; do not emit partial valid-looking terrain after a transform error. The later compiler contract defines sampling/interpolation and numeric tolerances.

Keep generic NAD83 approximation distinct from an actual realized 3D transformation. Root observed EPSG:1188 in this pinned database: generic NAD83 to WGS84, geog2D, stated 4 m operation accuracy. A future contract may explicitly select it for a documented horizontal prototype approximation; it must retain unknown source realization/epoch/error and cannot transform orthometric height or establish total 5 m accuracy. `allow_ballpark=False` does not make this published approximation survey accurate.

Root also observed EPSG:9595, NAD83(2011) 3D to NAD83(2011)+NAVD88 using GEOID18. Its inverse can provide compatible NAD83(2011) ellipsoid heights only when the source's frame/epoch/height provenance is established. It does not itself yield WGS84 ellipsoid height. Generic NAD83/UTM plus NAVD88 metadata is insufficient to claim that compatibility; a deliberate approximate vertical treatment needs a separate explicit limitation/operation contract. Do not promote FAA feet MSL to NAVD88, or NAVD88 to WGS84 ellipsoid height, by relabelling values. This pin contract selects neither operation for a terrain consumer.

## Decode and verification boundary

Pillow is only a proposed decoder here. Its tagged TIFF source supports single-band IEEE Float32 mode F and compressed TIFF through libtiff. Pre-use qualification must show that the exact selected Windows wheel faithfully decodes the actual pinned Float32 LZW USGS source tile, preserves NoData/nonfinite rejection and tags, and fits the bounded memory plan. Never convert elevation to 8-bit imagery. No decoder success, streaming capability, interpolation policy or terrain ABI is accepted by this tool lock.

Before any compiler consumer is accepted, retain a local receipt with the lock hash; interpreter identity; acquired wheel/grid hashes and sizes; complete installed wheel metadata/native/license inventory; loaded pyproj/Pillow/PROJ versions; database metadata and hash; sealed data manifest; offline/search-path checks including missing-grid refusal; and actual tile decode evidence. Preserve failed attempts. Source-only contract review can precede those executable checks; implementation must not claim they have passed merely because these pins merged.
